  <behavior>
    - CloudLoop._zmq_telemetry_collector stores latest value per ZMQ topic in self._telemetry_snapshot dict
    - When ZMQ sends [b"pcs", msgpack({ts, seq, src, topic, payload:{dc_voltage:400}})] the snapshot["pcs"] = {dc_voltage:400}
    - CloudLoop._periodic_publish fires at interval_s, builds JSON payload with all accumulated topics, calls publisher.publish_telemetry(), then clears snapshot
    - If snapshot is empty at publish time, no MQTT message is sent
    - Missing topics (no data since last publish) are omitted from payload
    - Payload format: {"ts": epoch_ms, "data": {"pcs": {...}, "bms.rack": [...], "system": {...}}}
    - CloudLoop._zmq_event_forwarder subscribes to SOCK_ALARM_PUB (alarm events) and forwards to publisher.publish_event() with QoS 1
    - Event forwarding only happens when publisher.connected is True
    - CloudLoop.run() starts all async tasks concurrently, stops on stop_event
    - CloudLoop.cleanup() closes all ZMQ sockets
  </behavior>

    IMPORTANT design decisions per CONTEXT.md:
    - Latest-value-wins for telemetry (store only most recent per topic)
    - Single consolidated MQTT message per interval (not per-topic)
    - JSON payload (not MessagePack) for MQTT
    - Omit topics with no data since last publish (do not send null/stale)
    - QoS 0 for telemetry (periodic, replaceable), QoS 1 for events (critical)
    - Event forwarding subscribes to SOCK_ALARM_PUB (alarm_manager's PUB socket), not SOCK_TELEMETRY
