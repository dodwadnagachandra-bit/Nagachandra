  <behavior>
**State constants** (match ems_control_state_t int values):
- STATE_INIT=0, STATE_IDLE=1, STATE_STANDBY=2, STATE_CHARGING=3, STATE_DISCHARGING=4, STATE_FAULT=5, STATE_EMERGENCY=6, STATE_MAINTENANCE=7

**Internal sub-states** (not exposed externally):
- _SubState.NONE, _SubState.STARTING, _SubState.STOPPING

**Constructor:** `ControlStateMachine(config: dict)` — takes the state_machine section of control_config. Starts in STATE_INIT. Extracts fault_retry_count, pcs_startup_timeout_s, pcs_shutdown_timeout_s.

**Core method:** `tick(self, now_s: float, pcs_state: int, pcs_fault_code: int, safety_emergency: bool, current_rtdb_state: int) -> TickResult`

Where `TickResult` is a dataclass:
```python
@dataclasses.dataclass
class TickResult:
    state: int                    # current control state (int matching ems_control_state_t)
    setpoint_kw: float            # active power setpoint to write to RTDB
    pcs_command: int              # PCS_CMD_* to write (0=NONE if no change)
    pcs_command_changed: bool     # True if pcs_command should increment seq
    state_changed: bool           # True if state transitioned this tick
    prev_state: int | None        # previous state if state_changed
    error_msg: str                # non-empty if a command was rejected
```

**Command methods (called by loop before tick):**
- `request_mode_change(target: str) -> tuple[bool, str]` — "standby" or "idle". Returns (ok, error_msg). Rejected if in EMERGENCY/MAINTENANCE (except maintenance_exit) or during STARTING/STOPPING sub-state.
- `request_manual_setpoint(power_kw: float) -> tuple[bool, str]` — Only valid in STANDBY/CHARGING/DISCHARGING. Stores pending setpoint.
- `request_fault_reset() -> tuple[bool, str]` — Only valid in FAULT. Sets _fault_reset_requested flag. Accepted even during retry countdown.
- `request_maintenance_enter() -> tuple[bool, str]` — From any non-EMERGENCY state.
- `request_maintenance_exit() -> tuple[bool, str]` — Only from MAINTENANCE.

**Transition test cases (RED phase):**
1. INIT -> IDLE: tick with pcs_state=OFF -> state becomes IDLE
2. IDLE -> STANDBY: request_mode_change("standby") + tick -> sub-state STARTING, pcs_command=ON
3. STARTING -> STANDBY: tick with pcs_state=RUNNING after 10s -> state becomes STANDBY
4. STARTING timeout: tick after 10s without RUNNING -> FAULT
5. STANDBY -> CHARGING: request_manual_setpoint(25.0) + tick -> CHARGING, setpoint=25.0
6. STANDBY -> DISCHARGING: request_manual_setpoint(-10.0) + tick -> DISCHARGING, setpoint=-10.0
7. CHARGING -> STANDBY: request_mode_change("standby") + tick -> sub-state STOPPING (zero setpoint, wait 2s, OFF not sent since PCS stays ON in STANDBY -- actually ramp to zero then stay in STANDBY)
8. Wait: CHARGING->STANDBY just sets setpoint to zero; once at zero, state is STANDBY. No PCS OFF needed.
9. STANDBY -> IDLE: request_mode_change("idle") + tick -> sub-state STOPPING, setpoint=0, after 2s pcs_command=OFF, wait 10s, IDLE
10. CHARGING -> DISCHARGING REJECTED: request that would skip STANDBY returns error
11. Any -> FAULT: tick with pcs_fault_code != 0 -> FAULT
12. FAULT auto-retry: after configurable count retries (3 default), each sends FAULT_RESET, waits for PCS recovery
13. FAULT manual reset: request_fault_reset() sets flag, tick sends FAULT_RESET and transitions to IDLE on success
14. Any -> EMERGENCY: tick with safety_emergency=True -> EMERGENCY, no commands sent
15. EMERGENCY -> IDLE: tick with safety_emergency=False -> IDLE (safety latch cleared)
16. Any -> MAINTENANCE: request_maintenance_enter() -> MAINTENANCE, pcs_command=OFF
17. MAINTENANCE -> IDLE: request_maintenance_exit() -> IDLE
18. MAINTENANCE persistence: if current_rtdb_state == STATE_MAINTENANCE on first tick, stay in MAINTENANCE
19. Commands rejected during STARTING: request_mode_change returns error with remaining time
20. Commands rejected during EMERGENCY: all requests return error
21. MAINTENANCE rejects all except maintenance_exit

**Clarifications per CONTEXT.md decisions:**
- CHARGING->STANDBY: Set setpoint to zero. No PCS OFF (PCS stays ON). Immediate transition once setpoint cleared.
- STANDBY->IDLE: Phase 14 ramp shortcut -- set zero, wait 2s, send OFF, wait 10s for PCS OFF confirmation.
- Direction change (CHARGING->DISCHARGING): MUST go CHARGING->STANDBY->DISCHARGING. Direct transition returns error.
  </behavior>
  <implementation>
Implement `ControlStateMachine` as a single class in state_machine.py:

- Use int constants for states (matching C enum values), not Python enum (avoids serialization hassle with ctypes).
- Use an `_SubState` enum (Python enum is fine since it is internal only).
- Store: `_state`, `_sub_state`, `_transition_start_s`, `_pending_setpoint_kw`, `_fault_retry_count`, `_fault_retries_done`, `_fault_reset_requested`, `_config`.
- The `tick()` method is the main entry point, called once per 1Hz cycle. It:
  1. Checks for EMERGENCY (highest priority — overrides everything)
  2. Checks for PCS fault (second priority — overrides normal transitions)
  3. Handles sub-state timers (STARTING, STOPPING)
  4. Processes pending commands (setpoint changes, mode changes)
  5. Returns TickResult with all outputs

- State transition validation: maintain a dict/set of valid (from_state, to_state) pairs per CONTEXT.md table. request_mode_change checks this before accepting.

- PCS command sequencing: TickResult includes pcs_command and pcs_command_changed. The caller (ControlLoop in Plan 03) handles incrementing pcs_command_seq in RTDB only when pcs_command_changed is True.

- Fault auto-retry: In FAULT state, track retry timer. Every pcs_startup_timeout_s seconds, send FAULT_RESET (up to fault_retry_count times). If all retries exhausted, stay in FAULT until manual reset.

No I/O in this class. No RTDB access, no ZMQ, no asyncio. Pure function of (current_state + inputs) -> (next_state + outputs).
  </implementation>
