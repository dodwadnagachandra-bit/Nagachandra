  <behavior>
    - GenericDevice with device_type="btms" writes to rtdb.btms section via seqlock
    - GenericDevice with device_type="meter" writes to rtdb.meter section via seqlock
    - GenericDevice maps register rtdb_field names to ctypes struct field setattr
    - startup_discovery probes one device at a time per port (sequential within port)
    - startup_discovery probes multiple ports in parallel (asyncio.gather)
    - Unreachable device is marked offline in RTDB, never blocks startup
    - Mandatory device (PCS) logs ERROR on unreachable; optional (BTMS) logs WARNING
    - Discovery completes within configurable timeout (default 30s total)
  </behavior>
  <action>
1. Create generic_device.py with GenericDevice(ModbusDevice):
   - Constructor takes additional `rtdb` and `rtdb_section_name` parameters. rtdb_section_name is one of "btms", "meter" (matching EmsRtdb field names). For DG and PV which lack dedicated RTDB structs, skip RTDB write (log values only) until RTDB is extended in a future phase.
   - `_write_to_rtdb(self, raw_values, now_ms)`:
     - Get section reference: `section = getattr(rtdb, self.rtdb_section_name, None)`
     - If section is None: return (DG/PV with no RTDB struct)
     - seqlock_write_begin(section.lock)
     - For each register with rtdb_field: setattr(section, reg.rtdb_field, scale_value(raw, reg))
     - section.last_update_ms = now_ms
     - seqlock_write_end(section.lock)
   - Priority constants per CONTEXT.md: PCS=0, Meter=1, BTMS=2, DG=3, PV=4
   - Poll interval from device config YAML (per CONTEXT.md: Meter 1000ms, BTMS/DG 2000ms, PV 1000ms)

2. Create discovery.py with:
   - `MANDATORY_DEVICES = {"pcs", "bms"}` (log ERROR on unreachable)
   - `async def startup_discovery(devices: list[ModbusDevice], clients: dict[str, AsyncModbusSerialClient], timeout_s: float = 30.0) -> dict[str, bool]`:
     - Groups devices by port
     - For each port group, creates async task that probes devices sequentially:
       a. For each device: try poll with short timeout (device.timeout_s or 3s, whichever smaller)
       b. If success: log INFO, mark online in RTDB, set device.health.online = True
       c. If failure: log ERROR for mandatory / WARNING for optional, mark offline in RTDB
     - await asyncio.gather(*port_tasks) with overall timeout
     - Returns dict[device_id, bool] (reachable/unreachable)
   - Never raises -- always returns, even if all devices unreachable

3. Update orchestrator.py:
   - Add `async def run_with_discovery(self)` that calls startup_discovery before entering polling loops
   - Log summary of discovery results: "Discovery complete: 3/5 devices reachable"

4. Update __main__.py:
   - Load all device configs (pcs, btms, meter, dg, pv) from profile-specific paths
   - Create GenericDevice instances for btms, meter (with RTDB section mapping)
   - Create GenericDevice instances for dg, pv (without RTDB section, log-only for now)
   - Wire all devices into CommOrchestrator
   - Call run_with_discovery() instead of run()
   - Add COMM-08 verification: log INFO "GPIO monitoring handled by safety_manager (SAFE-08)" at startup -- no GPIO code in comm_manager

5. Create test_generic_device.py:
   - Test GenericDevice writes to correct RTDB section (btms, meter)
   - Test GenericDevice with no RTDB section (dg, pv) does not crash
   - Test register mapping from rtdb_field names to struct fields

6. Create test_discovery.py:
   - Test discovery with all devices reachable
   - Test discovery with some devices unreachable (timeout)
   - Test discovery runs ports in parallel
   - Test mandatory vs optional logging difference
   - Test overall timeout
