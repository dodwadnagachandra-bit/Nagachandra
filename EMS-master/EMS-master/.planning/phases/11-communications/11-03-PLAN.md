   - `int comm_event_publish_with_data(comm_event_ctx_t *ctx, const char *event_type, const char *message, ems_severity_t severity, const char *device_id, int device_address);` -- extended payload with device_id and device_address in payload map

2. Create can_reader.h/.c:
   - Config struct: `typedef struct { const char *interface; uint32_t base_can_id; int cluster_index; int racks_per_cluster; ems_rtdb_t *rtdb; comm_event_ctx_t *event_ctx; } can_reader_config_t;`
   - `int can_socket_init(const char *interface);` -- creates CAN_RAW socket, binds to interface, enables CAN_RAW_ERR_FILTER with CAN_ERR_MASK, returns fd
   - `void *can_reader_thread(void *arg);` -- pthread entry point. Blocking read() loop on CAN socket:
     a. If frame.can_id has CAN_ERR_FLAG: call can_handle_error_frame(), update RTDB can_health via seqlock, publish can_bus_error event if bus_state changed
     b. Else: mask with CAN_EFF_MASK, call can_decode_id() to get cluster/rack/msg_offset, bounds-check cluster/rack against topology, call can_decode_frame() writing to correct ems_rack_t via seqlock, update rack->last_update_ms and set rack->online=1
   - On SIGTERM (via global volatile flag), break loop, close socket, return

3. Create can_health.h/.c:
   - `typedef struct { ems_rtdb_t *rtdb; comm_event_ctx_t *event_ctx; int cluster_count; int racks_per_cluster; uint32_t timeout_ms; volatile int *running; uint8_t prev_online[MAX_CLUSTERS][MAX_RACKS_PER_CLUSTER]; } can_health_config_t;`
   - `void *can_health_thread(void *arg);` -- pthread entry point. Runs at 300ms interval (fast_cycle_ms from config):
     a. For each active rack: read last_update_ms, compare to current CLOCK_MONOTONIC
     b. If stale > timeout_ms AND prev_online was 1: set rack->online=0 via seqlock, publish comm_fault event with fault_type="heartbeat_timeout", update prev_online
     c. If not stale AND prev_online was 0: rack came back online (can_reader_thread already set online=1), publish comm_recovery event, update prev_online
   - Initialize prev_online to 0 (all unknown at startup) to avoid false recovery events
   - Startup: set all rack last_update_ms to current CLOCK_MONOTONIC to avoid immediate false timeout (per RESEARCH.md pitfall 7)
