**tests/hw/__init__.py** — Empty package init.

**tests/hw/conftest.py** — Shared fixtures and constants:
- `ECU_IP` constant defaulting to `192.168.1.100`, overridable via `EMS_ECU_IP` env var.
- `ECU_USER` constant defaulting to `root`, overridable via `EMS_ECU_USER` env var.
- `DATA_DIR` constant: `/data` (ECU SSD mount point for Parquet data, logs).
- `EMS_VENV` constant: `/opt/ems/venv` (Yocto venv path from Phase 27 recipe).
- `SERVICES` list: all 14 runtime services (data_manager, ems-data-manager-python, config_manager, safety_manager, comm_manager_c, comm_manager, logger, control_manager, alarm_manager, scheduler, diagnostics, cloud_manager, ota_manager, hmi_server).
- `ecu_ssh(command: str) -> subprocess.CompletedProcess` fixture function — runs `ssh -o StrictHostKeyChecking=no -o ConnectTimeout=5 {ECU_USER}@{ECU_IP} {command}` via subprocess.run, captures stdout/stderr, returns CompletedProcess. NOT a pytest fixture — a plain helper function so it can be called multiple times per test.
- `ecu_reachable` session-scoped fixture — pings ECU_IP once at session start, skips all tests with `pytest.skip("ECU not reachable")` if ping fails. This allows `uv run pytest tests/hw/` to gracefully skip when no hardware is connected.
- `pytestmark = [pytest.mark.hw]` module-level marker for all hw tests.
- Add `markers = ["hw: hardware validation tests (require ECU connection)"]` note in a comment for pyproject.toml update.

**tests/hw/test_boot.py** — Stage 1: Boot Validation:
- `test_all_services_active` — Loops through SERVICES list, runs `ecu_ssh("systemctl is-active {svc}")` for each, asserts stdout.strip() == "active". Collects failures into a list, asserts empty at end for clear error reporting (shows all failed services, not just first).
- `test_boot_time_within_60s` — Runs `ecu_ssh("systemd-analyze")` and parses the total boot time. Asserts < 60 seconds. If systemd-analyze is unavailable, marks as xfail.
- `test_ems_target_active` — Asserts `systemctl is-active ems.target` returns "active".
- `test_no_failed_services` — Runs `systemctl list-units --state=failed --no-legend`, asserts no EMS services appear in the output.
- All tests use `@pytest.mark.usefixtures("ecu_reachable")` to auto-skip when ECU is offline.
- Module-level `pytestmark = [pytest.mark.hw, pytest.mark.timeout(120)]`.

**tools/hw-validation/stage1-boot.sh** — Standalone bash script (no pytest dependency):
- Accepts ECU_IP as first argument (default 192.168.1.100).
- Loops through all 14 services with 60-second total timeout.
- Prints PASS/FAIL per service, summary at end.
- Exits 0 if all pass, 1 otherwise.
- Use the exact script pattern from RESEARCH.md Pattern 2.
- Make executable (chmod +x).

Create driver verification tests for Stage 2 — each hardware interface tested independently.

**tests/hw/test_drivers.py** — Stage 2: Per-Driver Verification:

Module-level: `pytestmark = [pytest.mark.hw, pytest.mark.timeout(300)]`

CAN tests:
- `test_can0_interface_exists` — `ecu_ssh("ip link show can0")` returns 0 exit code. If fails, adds diagnostic: `ecu_ssh("dmesg | grep -i can | tail -10")`.
- `test_can1_interface_exists` — Same for can1.
- `test_can0_up_and_configured` — `ecu_ssh("ip -d link show can0")` output contains "state UP" or verifies interface can be brought up with `ip link set can0 up type can bitrate 250000`.
- `test_can_loopback` — If both CAN0 and CAN1 exist, set CAN0 to loopback mode (`ip link set can0 type can loopback on`), send a frame with `cansend can0 123#DEADBEEF`, verify `candump can0 -n 1 -T 2000` receives it. Clean up loopback mode after.

RS485 tests (device existence):
- `test_rs485_1_exists` — `ecu_ssh("test -c /dev/ttyS1 || test -c /dev/ttyS3")` — check expected UART device exists. Note: actual device path depends on DTB; test checks common paths and reports which exists.
- `test_rs485_2_exists`, `test_rs485_3_exists`, `test_rs485_4_exists` — Same pattern for remaining UART paths. Each test checks `/dev/ttyS{N}` for N in likely range and reports findings.
- `test_rs485_stty_config` — For each found ttyS device, verify `stty -F /dev/ttySN` succeeds (device is configurable). Check baud rate can be set to 9600.

RS485 Modbus polling tests (per user decision — locked requirement that each RS485 port verifies ECU can poll Modbus registers):
- `test_rs485_modbus_poll` — Marked with `@pytest.mark.requires_simulator` (auto-skips if no simulator detected). For each RS485 port (1-4), attempts a Modbus RTU read of holding registers via the ECU's `comm_manager` or a direct `pymodbus` call over the serial device. The test flow:
  1. For each discovered ttyS device, use `ecu_ssh` to run a short Python snippet on the ECU: `python3 -c "from pymodbus.client import ModbusSerialClient; c = ModbusSerialClient('/dev/ttySN', baudrate=9600, timeout=2); c.connect(); r = c.read_holding_registers(0, 1, slave=1); print('OK' if not r.isError() else 'ERR'); c.close()"`
  2. If a Modbus simulator is running on the other end of the RS485 cable, the read succeeds (prints "OK"). If no simulator, the read times out (prints "ERR") and the test is marked as xfail with reason "No Modbus simulator detected on port N".
  3. The `@pytest.mark.requires_simulator` marker is implemented as a custom marker in conftest.py — it does NOT auto-skip by itself. Instead, the test body detects timeout/connection-refused and calls `pytest.xfail("No simulator on /dev/ttySN")` per-port. Ports that respond are asserted as OK.
  4. This distinguishes "UART exists but nothing responds" (expected without simulator) from "UART exists and Modbus communication works" (full validation).
- This test validates the locked decision from CONTEXT.md: "RS485-1 (PCS): ECU polls and decodes registers", "RS485-2 (Meter): ECU reads meter telemetry", etc.

GPIO tests:
- `test_gpiochip_exists` — `ecu_ssh("gpiodetect")` returns at least one gpiochip device. Parse output, store chip names in test output for reference.
- `test_gpiochip_lines` — `ecu_ssh("gpioinfo")` succeeds, output contains lines for the expected GPIO bank. At minimum 16 lines (8 DI + 8 DO) must be available on at least one chip.
- `test_gpio_di_readable` — For each DI line (0-7), attempt `gpioget {chipname} {offset}` and verify it returns 0 or 1 (not an error). Use the first gpiochip from gpiodetect.
- `test_gpio_do_writable` — Attempt `gpioset {chipname} {offset}=1` then `gpioset {chipname} {offset}=0` for a safe DO line (DO-3 RUNNING_LAMP or DO-7 SPARE). Verify commands succeed. Do NOT actuate safety-critical outputs (DO-0 ACDB_TRIP, DO-1 EXTINGUISHER, DO-5 PCS_STOP).

Network tests:
- `test_eth_interfaces` — `ecu_ssh("ip -br link show")` — verify at least 2 Ethernet interfaces exist. Report actual names (eth0/eth1 or predictable names).
- `test_eth0_link_up` — Check first Ethernet interface has link state UP when cable connected.
- `test_network_connectivity` — `ecu_ssh("ping -c 3 -W 2 8.8.8.8")` — verify WAN connectivity (may fail in isolated lab; mark as xfail).

HDMI test:
- `test_hdmi_output_detected` — `ecu_ssh("cat /sys/class/drm/card*/status 2>/dev/null || echo 'no drm'")` — check if DRM subsystem detects a connected display. Note: may show "disconnected" if no monitor plugged in; test just verifies DRM subsystem exists.

All tests should have clear docstrings explaining what they verify, what the expected stimulus is, and what failure means for hardware bring-up.

**tools/hw-validation/stage2-drivers.sh** — Standalone bash script:
- Accepts ECU_IP as first argument.
- Runs CAN, RS485, GPIO, ETH, HDMI checks via SSH commands.
- Groups output by driver category with clear headers.
- **RS485 section has two distinct steps per port:**
  1. "UART exists" — checks `/dev/ttySN` character device exists (PASS/FAIL)
  2. "Modbus poll" — attempts a Modbus register read via a Python one-liner on the ECU (PASS/FAIL/SKIP if no simulator). Uses the same pymodbus snippet as the pytest test.
- Reports PASS/FAIL per check, summary at end. The summary distinguishes "N/M hardware checks passed" from "N/M communication checks passed (K skipped — no simulator)".
- Make executable.
