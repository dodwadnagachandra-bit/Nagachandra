# Phase 13.1 Plan 01: Fix ZMQ Framing Defects Summary

Fixed 3 ZMQ framing defects that caused silent message loss across the C/Python boundary by aligning C senders with the Python framing convention.

## What Was Done

### DEFECT-1: Double ZMQ PUB Bind (CRITICAL)

HealthMonitor was creating and binding its own PUB socket on the same SOCK_TELEMETRY endpoint that TelemetryPublisher already bound. The second bind() would fail with "Address already in use."

**Fix:** Changed HealthMonitor to accept a shared PUB socket via constructor injection. Added `pub_socket` property to TelemetryPublisher. Updated `__main__.py` to pass the shared socket. HealthMonitor.close() is now a no-op since it does not own the socket lifecycle.

### DEFECT-2: C PUSH Framing Mismatch (HIGH)

C PUSH senders (safety_event.c, comm_event.c) sent multipart `[4-byte BE length prefix | SNDMORE] [msgpack body]`. Python PULL receiver (event_writer.py) does single-frame `recv()`, getting the 4-byte length prefix as data, causing `decode_event()` to fail.

**Fix:** Removed length prefix frame from C PUSH sends. Now sends single frame containing just the msgpack body.

### DEFECT-3: C PUB Framing Mismatch (HIGH)

C PUB senders sent 3 frames `[topic | len | body]`. Python SUB receiver (telemetry_writer.py) drops anything != 2 frames.

**Fix:** Removed length prefix frame from C PUB sends. Now sends 2 frames `[topic | body]`.
