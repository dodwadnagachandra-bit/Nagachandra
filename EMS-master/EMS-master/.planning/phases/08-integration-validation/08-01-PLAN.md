  <name>Task 1: Extend JSON schemas with fault_injection and signal_tuning sections</name>
  <files>config/schemas/bms_config.schema.json, config/schemas/pcs_config.schema.json, config/schemas/gpio_config.schema.json</files>
  <action>
Update schemas FIRST (before any YAML changes). All three schemas use `additionalProperties: false` at every level (locked Phase 2 decision), so new config sections must be in the schema or validation fails.

**bms_config.schema.json** — add two optional top-level properties:

1. `fault_injection` (type: object, additionalProperties: false):
   - `frame_drop_rate` (number, minimum: 0.0, maximum: 1.0) — fraction of CAN frames to silently drop
   - `corrupt_data` (boolean) — enable occasional garbled signal values
   - `corrupt_rate` (number, minimum: 0.0, maximum: 1.0, optional) — corruption probability per frame (default 0.02 in code)
   - `stale_timeout_ms` (integer, minimum: 0) — stop sending for rack 0 for this many ms after startup
   - `stale_rack_index` (integer, minimum: 0, optional) — which rack goes stale (default 0)

2. `signal_tuning` (type: object, additionalProperties: false):
   - `noise_sigma` (number, minimum: 0.0) — Gaussian noise standard deviation for cell voltage
   - `drift_amplitude` (number, minimum: 0.0) — sinusoidal drift amplitude in volts
   - `drift_period_s` (number, exclusiveMinimum: 0.0) — drift period in seconds
   - `base_voltage` (number, minimum: 2.5, maximum: 4.2) — base cell voltage

**pcs_config.schema.json** — add two optional top-level properties:

1. `fault_injection` (type: object, additionalProperties: false):
   - `response_timeout` (boolean) — simulator stops responding
   - `timeout_duration_s` (number, minimum: 0.0) — how long to not respond
   - `exception_code` (integer, minimum: 1, maximum: 4) — Modbus exception code
   - `exception_registers` (array of integers) — register addresses that return exceptions

2. `signal_tuning` (type: object, additionalProperties: false):
   - `ramp_rate_pct_per_s` (number, minimum: 0.0) — telemetry ramp rate
   - `startup_delay_s` (number, minimum: 0.0) — delay before telemetry starts
   - `voltage_noise` (number, minimum: 0.0) — noise on voltage readings

**gpio_config.schema.json** — add one optional top-level property:

1. `fault_injection` (type: object, additionalProperties: false):
   - `stuck_pins` (array of integers, items minimum: 0, maximum: 7) — DI pins that ignore writes
   - `stuck_values` (object, optional) — pin-to-value mapping for stuck pin state
   - `bounce_ms` (integer, minimum: 0) — contact bounce duration in milliseconds

After editing schemas, run `uv run python tools/validate_config.py` to confirm all existing configs still pass (backward compatibility — new sections are optional, not required).

  <action>
Implement config-driven fault injection in all 3 simulators. Faults are read from YAML at startup and apply for the lifetime of the process. No runtime injection, no IPC needed.

**CAN Simulator (3 files):**

1. `simulator.py` — In `CANSimulator.__init__`, after loading bms_config YAML, extract `fault_injection` and `signal_tuning` dicts (defaulting to empty dict if absent). Pass `fault_cfg` dict to each `RackSimulator` constructor. Pass `tuning_cfg` dict to each `SignalGenerator` constructor (via `RackSimulator`).

2. `rack.py` — Add `fault_cfg: dict` parameter to `RackSimulator.__init__`:
   - Store `self.frame_drop_rate = fault_cfg.get("frame_drop_rate", 0.0)`
   - Store `self.corrupt_data = fault_cfg.get("corrupt_data", False)`
   - Store `self.corrupt_rate = fault_cfg.get("corrupt_rate", 0.02)`
   - Store `self.stale_timeout_ms = fault_cfg.get("stale_timeout_ms", 0)`
   - Store `self.stale_rack_index = fault_cfg.get("stale_rack_index", 0)`
   - Compute `self._stale_until`: if `stale_timeout_ms > 0` and `rack_index == stale_rack_index`, set to `time.monotonic() + stale_timeout_ms / 1000.0`, else 0.0
   - In `_send_frame()`, add at TOP of method (before encoding):
     - If `time.monotonic() < self._stale_until`: return (suppress all frames)
     - If `self.frame_drop_rate > 0 and random.random() < self.frame_drop_rate`: log debug and return
   - In `_send_frame()`, AFTER encoding data bytes but BEFORE bus.send():
     - If `self.corrupt_data and random.random() < self.corrupt_rate`: pick random byte index, replace with random value, log debug
   - Import `random` and `time` at top of file

3. `signals.py` — Add `tuning: dict | None = None` parameter to `SignalGenerator.__init__`:
   - Store tuning params with defaults matching current hardcoded values: `noise_sigma` (0.005), `drift_amplitude` (0.15), `drift_period_s` (60.0), `base_voltage` (3.35)
   - In `cell_voltage()`: replace hardcoded `0.15` with `self.drift_amplitude`, `60.0` with `self.drift_period_s`, `0.005` with `self.noise_sigma`, `3.35` with `self.base_voltage`
   - Ensure defaults exactly match current hardcoded values so behavior is unchanged when no tuning config is provided

**Modbus Simulator (2 files):**

1. `simulator.py` — In `ModbusSimulator.__init__`, extract `fault_cfg = pcs_cfg.get("fault_injection", {})`:
   - Pass `fault_cfg` to `CallbackDataBlock` constructor (or store on simulator and pass relevant parts)
   - If `fault_cfg.get("response_timeout", False)`: add a startup delay of `fault_cfg.get("timeout_duration_s", 10.0)` seconds before starting the Modbus server (use `await asyncio.sleep(delay)` in `run()` before server start)
   - Extract `signal_tuning = pcs_cfg.get("signal_tuning", {})` and pass to `PCSSignalGenerator` if it accepts tuning params, or apply `startup_delay_s` and `voltage_noise` in `_update_registers()`

2. `register_map.py` — In `CallbackDataBlock`, add fault injection support:
   - Add `fault_cfg: dict` parameter to `__init__` (or a setter method)
   - Store `self._exception_registers = set(fault_cfg.get("exception_registers", []))` and `self._exception_code = fault_cfg.get("exception_code", 0x02)`
   - In `getValues()`: if `address in self._exception_registers`, raise a `ModbusException` or return values that indicate an exception. NOTE: pymodbus server framework handles exceptions differently than returning ExceptionResponse from getValues. The cleanest approach is to check in the `_ZeroModeDeviceContext.getValues()` method in simulator.py and raise `pymodbus.exceptions.NoSuchSlaveException` or use the `ModbusException` mechanism. Research the exact pymodbus 3.12 pattern — the simplest approach may be to return `None` or an empty list from `getValues` to trigger a default exception, or to set specific register values to indicate fault state.

**GPIO Harness (1 file):**

   - Store `self._bounce_ms: int = fault_cfg.get("bounce_ms", 0)` if fault_cfg else 0
