  <name>Task 1: Create sim-all.sh launcher and Makefile target</name>
  <files>tools/sim-all.sh, Makefile, .gitignore</files>
  <action>
Create `tools/sim-all.sh` — a bash script that launches all 3 simulators simultaneously with process management.

**Script structure:**
```
#!/usr/bin/env bash
set -euo pipefail
```

1. Parse arguments: `--profile` (default: residential), `--verbose` flag, `--tcp-port` for Modbus (default: 5020)

2. Derive config paths from profile:
   - `CONFIG_DIR="config/profiles/$PROFILE"`
   - Validate that `$CONFIG_DIR` exists, exit 1 if not

3. Create `logs/` directory if not exists (`mkdir -p logs`)

4. Set up vcan0 (same pattern as Makefile sim-can target):
   ```
   sudo modprobe vcan can can_raw 2>/dev/null || true
   sudo ip link add dev vcan0 type vcan 2>/dev/null || true
   sudo ip link set up vcan0 2>/dev/null || true
   ```

5. Set up PID tracking and cleanup trap:
   ```
   PIDS=()
   cleanup() {
       echo "Shutting down simulators..."
       for pid in "${PIDS[@]}"; do kill "$pid" 2>/dev/null || true; done
       wait 2>/dev/null
       echo "All simulators stopped."
   }
   trap cleanup EXIT INT TERM
   ```

6. Launch all 3 simulators in background:
   - CAN: `uv run python -m tools.simulators.can_sim --interface vcan0 --config "$CONFIG_DIR/bms_config.yaml" $VERBOSE_FLAG > logs/sim-can.log 2>&1 &`
   - Modbus: `uv run python -m tools.simulators.modbus_sim --transport tcp --tcp-port "$TCP_PORT" --config "$CONFIG_DIR/pcs_config.yaml" $VERBOSE_FLAG > logs/sim-modbus.log 2>&1 &`
   - GPIO: `uv run python -m tools.simulators.gpio_harness daemon --backend rtdb $VERBOSE_FLAG > logs/sim-gpio.log 2>&1 &`
   - Store each PID in PIDS array

   NOTE: Use TCP mode for Modbus (not RTU) to avoid socat dependency. This matches the CI integration test approach.

   NOTE: GPIO harness may need a `daemon` subcommand. Check if it exists — if not, the harness may not need a long-running process. In that case, just create the shm segment and leave it. The GPIO harness is stateless (RTDB-backed), so the integration test can interact with it directly without a daemon. If no daemon mode exists, skip launching GPIO as a background process and just note in the summary status that GPIO is RTDB-backed (no daemon needed).

7. Implement `wait_for_health` function:
   ```
   wait_for_health() {
       local name="$1" check_cmd="$2" timeout=5 elapsed=0
       while ! eval "$check_cmd" 2>/dev/null; do
           sleep 0.5
           elapsed=$((elapsed + 1))
           if [ "$elapsed" -ge "$((timeout * 2))" ]; then
               echo "FAIL: $name health check timed out after ${timeout}s" >&2
               return 1
           fi
       done
   }
   ```

8. Run health checks:
   - CAN: `wait_for_health "CAN" "ip link show vcan0 | grep -q UP"`
   - Modbus: `wait_for_health "Modbus" "ss -tln | grep -q :$TCP_PORT"`
   - GPIO: `wait_for_health "GPIO" "ls /dev/shm/ems_rtdb* 2>/dev/null"`

9. Print summary status line:
   ```
   echo "CAN: running (vcan0) | Modbus: running (TCP, :$TCP_PORT) | GPIO: running (RTDB)"
   echo "Profile: $PROFILE | Logs: logs/sim-*.log"
   echo "Press Ctrl+C to stop all simulators."
   ```

10. `wait` on all PIDs (blocks until Ctrl+C triggers cleanup)

Make the script executable: `chmod +x tools/sim-all.sh`

**Makefile** — add `sim-all` target:
```
sim-all: ## Start all simulators (CAN + Modbus + GPIO)
	bash tools/sim-all.sh --profile $(or $(PROFILE),residential)
```

**`.gitignore`** — add `logs/` directory if not already present.

Create `tests/test_integration.py` with `@pytest.mark.integration` marker. The test suite starts simulators as subprocesses, exercises one operation per simulator, validates fault injection, and tears down cleanly. Total runtime target: under 30 seconds.

**pyproject.toml** — add `integration` marker to `[tool.pytest.ini_options]` markers list:
```
"integration: Integration tests requiring simulators (deselect with: -m 'not integration')",
```

**tests/test_integration.py:**

1. Module-level setup: skip entire module if vcan0 cannot be created (CI handles this, but local dev may not have permissions):
   ```python
   pytestmark = pytest.mark.integration
   ```

2. Fixture `vcan0_up` (session scope): ensure vcan0 interface is up. Run `ip link show vcan0` — if fails, `pytest.skip("vcan0 not available")`.

3. Fixture `can_sim_process` (module scope): start CAN simulator as subprocess with residential profile config. Use `subprocess.Popen(["uv", "run", "python", "-m", "tools.simulators.can_sim", "--interface", "vcan0", "--config", "config/profiles/residential/bms_config.yaml"])`. Wait 2 seconds for startup. Yield process. On teardown: `proc.terminate()`, `proc.wait(timeout=5)`, if timeout `proc.kill()`.

4. Fixture `modbus_sim_process` (module scope): start Modbus simulator in TCP mode on port 5020. `subprocess.Popen(["uv", "run", "python", "-m", "tools.simulators.modbus_sim", "--transport", "tcp", "--tcp-port", "5020", "--config", "config/profiles/residential/pcs_config.yaml"])`. Wait 2 seconds. Yield. Teardown same as CAN.

5. Fixture `gpio_backend` (module scope): create an `RtdbBackend` instance with a unique shm name (`f"ems_rtdb_inttest_{os.getpid()}"`). Yield backend. On teardown: `backend.close()`.

6. Test `test_can_sends_frames(vcan0_up, can_sim_process)`:
   - Create a `can.Bus(interface="vcan0", channel="vcan0", bustype="socketcan")` with a short timeout (2s)
   - Read one message: `msg = bus.recv(timeout=3.0)`
   - Assert msg is not None (a frame was received)
   - Assert `msg.is_extended_id` is True (29-bit CAN ID)
   - Cleanup: bus.shutdown()

7. Test `test_modbus_read_write(modbus_sim_process)`:
   - Use `pymodbus.client.AsyncModbusTcpClient` to connect to `localhost:5020`
   - Read holding register 0x500E (active power): assert successful response
   - Write to register 0x0291 (on/off command): assert successful response
   - Read back 0x0291: assert value matches what was written
   - Cleanup: client.close()
   - Use `asyncio.run()` or make the test async with pytest-asyncio

8. Test `test_gpio_set_and_read(gpio_backend)`:
   - `gpio_backend.set_di(0, 1)` (set ACDB pin)
   - `value = gpio_backend.get_di(0)`
   - Assert value == 1
   - `gpio_backend.set_di(0, 0)` (clear)
   - Assert `gpio_backend.get_di(0) == 0`

9. Test `test_can_fault_injection(vcan0_up)`:
   - Create a temporary bms_config YAML with `fault_injection: {frame_drop_rate: 1.0}` (drop ALL frames)
   - Start CAN sim subprocess with this config
   - Try to receive a frame with 3s timeout
   - Assert msg is None (no frames because 100% drop rate)
   - Teardown subprocess

10. Test `test_modbus_fault_injection()`:
    - Create a temporary pcs_config YAML with `fault_injection: {response_timeout: true, timeout_duration_s: 30}` (30s timeout — longer than test)
    - Start Modbus sim subprocess with this config and TCP mode on port 5021 (different port to avoid conflicts)
    - Try to connect and read — should fail/timeout within 3s
    - Teardown subprocess

11. Test `test_gpio_fault_injection()`:
    - Create RtdbBackend with fault_cfg `{"stuck_pins": [3]}`
    - `backend.set_di(3, 1)` — should be ignored (stuck)
    - Assert `backend.get_di(3) == 0` (pin 3 stayed at default 0, write was ignored)
    - `backend.set_di(0, 1)` — non-stuck pin should work
    - Assert `backend.get_di(0) == 1`

For temporary config files, use `tmp_path` pytest fixture or `tempfile.NamedTemporaryFile`. The temp configs should be valid YAML files that include all required fields from the schema (can, timing for bms; pcs for pcs_config) plus the fault_injection section.
