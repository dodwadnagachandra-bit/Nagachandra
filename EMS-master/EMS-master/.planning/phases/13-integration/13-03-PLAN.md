Create `tests/integration/test_e2e_pipeline.py` with these components:

**Module-level marker:** `pytestmark = [pytest.mark.integration, pytest.mark.timeout(300)]`

**Imports:** pytest, time, json, random, subprocess, Path, tempfile, pyarrow.parquet as pq, duckdb, zmq, msgpack. From conftest: ModuleProcess, PROFILES, BUILD_DIR, CONFIG_DIR, check_rtdb_exists. From ems_common: ipc constants, rtdb helpers.

**DETERMINISTIC_SEED = 42** -- used to seed simulators for reproducible data.

**Class TestEndToEndPipeline:**

Fixture `pipeline_env` (class scope): Sets up the full pipeline for a single test topology run:
1. Create a temp directory for data output (Parquet, JSONL)
2. Set `random.seed(DETERMINISTIC_SEED)` for reproducibility
3. Launch modules in order using ModuleProcess:
   - data_manager_c with residential topology args
   - data_manager_python
   - config_manager (with profile config_dir)
   - safety_manager (skip if binary not found)
   - comm_manager_c (skip if vcan0 unavailable)
   - comm_manager_python (with profile config_dir)
   - logger (with config pointing to temp data dir if possible, else default)
4. Launch simulators as subprocesses:
   - CAN simulator: `["uv", "run", "python", "-m", "tools.simulators.can_sim", "--interface", "vcan0", "--config", str(config_dir / "bms_config.yaml")]` -- skip if no vcan0
   - Modbus simulator: `["uv", "run", "python", "-m", "tools.simulators.modbus_sim", "--transport", "tcp"]`
5. Wait 35 seconds for data to flow through the pipeline (logger needs time to write Parquet)
6. Yield a dict with: `{"modules": [...], "simulators": [...], "data_dir": temp_dir, "profile": profile}`
7. Teardown: kill all simulators, then all modules in reverse order, cleanup temp dir

Test methods:

1. `test_rtdb_has_data(self, pipeline_env)`:
   - Attach to RTDB
   - Read a BMS rack section -- verify cell voltages are non-zero (CAN data arrived)
   - Read PCS section -- verify at least one field is non-zero (Modbus data arrived)
   - Detach RTDB

2. `test_parquet_files_created(self, pipeline_env)`:
   - Search pipeline_env["data_dir"] for `telemetry_*.parquet` files (rglob)
   - Assert at least 1 Parquet file exists
   - Read first file with pyarrow: assert `table.num_rows >= 25`
   - Verify schema contains expected columns (timestamp, at least one telemetry field)

3. `test_parquet_data_matches_simulator(self, pipeline_env)`:
   - Read Parquet telemetry file with pyarrow
   - Use DuckDB to query: `SELECT pack_soc FROM telemetry WHERE pack_soc IS NOT NULL`
   - Assert SOC values are in valid range (20.0 - 80.0 +/- 1% tolerance)
   - Assert at least 25 non-null data points

4. `test_duckdb_query_returns_results(self, pipeline_env)`:
   - Find Parquet files in data_dir
   - Open DuckDB connection, create view over Parquet
   - Query `SELECT COUNT(*) FROM telemetry` -- assert > 0
   - Query `SELECT MIN(timestamp), MAX(timestamp) FROM telemetry` -- assert time range spans at least 20 seconds

5. `test_jsonl_events_valid(self, pipeline_env)`:
   - Search data_dir for `events_*.jsonl` files (rglob in `events/` subdir)
   - If no JSONL files found (events may not have been generated in clean run), skip with message
   - Otherwise: read each line, parse as JSON, verify each event has required fields: `timestamp`, `source`, `type`
   - Assert file is not empty (at least 1 event line)

6. `test_zmq_telemetry_received(self, pipeline_env)`:
   - Create ZMQ SUB socket, subscribe to all topics
   - Connect to telemetry endpoint (use TCP if ipc unavailable)
   - Receive at least 1 message within 5 seconds
   - Decode with msgpack, verify it has expected structure (topic + payload)

7. `test_duckdb_query_via_zmq_api(self, pipeline_env)`:
   - Create ZMQ REQ socket, connect to SOCK_LOGGER_QUERY endpoint
   - Send a time_series query request (msgpack-encoded dict with query_type="time_series", signal="pack_soc", start/end timestamps covering the test window)
   - Receive response within 5 seconds
   - Decode response with msgpack
   - Assert response contains at least 25 data points
   - Assert SOC values in response are within valid range (20.0-80.0 +/- 1%)
   - This validates CONTEXT.md E2E step 3: "Query time_series for pack_soc via ZMQ REQ/REP"

**Important implementation notes:**
- Use `tempfile.mkdtemp(prefix="ems_integ_")` for data output isolation
- Set environment variable `EMS_DATA_DIR` or pass `--data-dir` to logger if supported, otherwise use default data/ dir and clean up after
- The 35-second wait is necessary because: CAN sim needs ~1s to start sending, comm_manager needs ~2s to decode and write RTDB, data_manager publishes at 1Hz, logger collects for 1s then writes. 30s of data + 5s startup = 35s total.
- For DuckDB assertions: use +-1% tolerance on SOC values (SignalGenerator adds Gaussian noise)
- Skip CAN-related assertions if vcan0 was unavailable (comm_manager_c was skipped)
- All subprocess cleanup must use try/finally and os.killpg for process groups
