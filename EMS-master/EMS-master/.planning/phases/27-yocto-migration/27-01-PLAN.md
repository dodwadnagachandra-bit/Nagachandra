  <action>
    Create the complete `yocto/meta-ems/` directory tree per the CONTEXT.md locked structure.

    **layer.conf:**
    - BBPATH, BBFILES for recipes-*/*/*.bb and *.bbappend
    - BBFILE_COLLECTIONS = "meta-ems", BBFILE_PRIORITY = 10
    - LAYERDEPENDS_meta-ems = "core meta-ti-bsp meta-oe meta-python"
    - LAYERSERIES_COMPAT_meta-ems = "scarthgap"

    **am65xx-ems.conf (custom MACHINE):**
    - `require conf/machine/am65xx-evm.conf` (from meta-ti-bsp)
    - Override SERIAL_CONSOLES for ECU-1170 (ttyS2,115200)
    - Set UBOOT_MACHINE = "am65x_evm_a53_defconfig" (starting point, Phase 29 validates)
    - MACHINE_FEATURES include "ext4 vfat efi"
    - Add a comment that exact DTB and U-Boot config depend on Advantech BSP (deferred to Phase 29)

    **C binary recipes (5 total):**
    Each C recipe follows the cmake bbclass pattern from RESEARCH.md:
    - `inherit cmake externalsrc`
    - EXTERNALSRC points to monorepo source: `${TOPDIR}/../../src/<module>` (safety_manager at root, others at c/ subdirectory)
    - EXTERNALSRC_BUILD = "${WORKDIR}/build"
    - DEPENDS includes ems-common-c plus module-specific deps (libzmq, libgpiod for safety_manager; libzmq, libmodbus for comm_manager_c; libzmq for data_manager_c and control_manager_c)
    - EXTRA_OECMAKE = "-DCMAKE_BUILD_TYPE=Release"
    - Install to /opt/ems/bin/ via do_install()
    - FILES:${PN} = "/opt/ems/bin/<binary_name>"
    - Do NOT set CMAKE_TOOLCHAIN_FILE in EXTRA_OECMAKE (cmake bbclass handles it)
    - LICENSE = "CLOSED"
    - Note: ems-common-c recipe installs shared library to /opt/ems/lib/ and headers to /opt/ems/include/

    Source directories for EXTERNALSRC (verify these exist in monorepo):
    - ems-common-c: src/common/c/
    - safety-manager: src/safety_manager/ (CMakeLists.txt at root)
    - comm-manager-c: src/comm_manager/c/
    - data-manager-c: src/data_manager/c/
    - control-manager-c: src/control_manager/c/

    **ems-python-venv recipe:**
    NOTE: CONTEXT.md specifies `python3-setuptools` class with individual recipes per module.
    However, per RESEARCH.md findings, `python_setuptools_build_meta` does NOT support the
    `uv_build` backend used by this project's Python packages in Yocto Scarthgap. Therefore,
    this plan uses a wheel-staging approach (FILES class) as a justified deviation:
    - Uses FILES class (not python3-setuptools — the uv_build backend is incompatible with Yocto's setuptools_build_meta bbclass in Scarthgap)
    - SRC_URI includes all pre-built wheel files from a `wheels/` directory (populated by build pipeline)
    - Installs wheels to /opt/ems/python/wheels/
    - Installs requirements.lock to /opt/ems/python/requirements.lock
    - The actual venv creation happens in core-image-ems.bb via ROOTFS_POSTPROCESS_COMMAND
    - Add a comment in the recipe explaining: "Deviation from CONTEXT.md python3-setuptools decision: uv_build backend is not supported by python_setuptools_build_meta in Scarthgap. Wheels are pre-built offline and staged here; venv is created during image build."

    **ems-config recipe:**
    - FILES class, copies all 14 YAML configs + 16 JSON schemas + 3 profiles from config/
    - Installs to /etc/ems/config/
    - SRC_URI points to monorepo config/ directory via EXTERNALSRC pattern

    **ems-systemd-units recipe:**
    - inherit systemd
    - Copies all service files from deploy/systemd/ to /usr/lib/systemd/system/
    - SYSTEMD_SERVICE:${PN} lists all 14 .service files + ems.target
    - SYSTEMD_AUTO_ENABLE = "enable"

    **ems-frontend recipe:**
    - FILES class, copies pre-built dist/ from src/hmi_server/frontend/dist/
    - Installs to /opt/ems/frontend/dist/
    - No bun/Node.js dependency — frontend is pre-built on dev machine

    **libubootenv bbappend:**
    - Installs /etc/fw_env.config for ECU-1170 eMMC layout
    - Device: /dev/mmcblk0, offset: 0x3E0000, size: 0x20000, sector: 0x200
    - Add comment that offset must be verified against actual ECU-1170 U-Boot defconfig in Phase 29

    **setup-yocto.sh:**
    - Script to initialize the Yocto build environment
    - Clones poky (scarthgap branch), meta-ti (scarthgap), meta-openembedded (scarthgap)
    - Sources oe-init-build-env
    - Adds meta-ems, meta-ti-bsp, meta-oe, meta-python to bblayers.conf
    - Sets MACHINE = "am65xx-ems" in local.conf
    - Make it executable (chmod +x)
