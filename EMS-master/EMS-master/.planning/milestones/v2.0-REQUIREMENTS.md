# Requirements: ReVx EMS

**Defined:** 2026-03-13
**Core Value:** Reliable, safe control of battery energy storage — safety manager protects equipment and people, control loop maintains correct power dispatch, system never loses telemetry data.

## v2.0 Requirements

Requirements for M1 — Core Infrastructure. Each maps to roadmap phases.

### Communications (comm_manager)

- [x] **COMM-01**: CAN DBC decode via SocketCAN C thread reads all 12 L2 message types (0x98FF0003–0x98FF0903) and writes decoded signals to RTDB BMS sections with seqlock
- [x] **COMM-02**: CAN heartbeat timeout detects per-rack BMU silence (default 3x cycle = 900ms), sets rack offline in RTDB, and publishes comm_fault event
- [x] **COMM-03**: CAN bus-off and error-frame handling reads SocketCAN error frames (CAN_ERR_FLAG), logs TEC/REC counts, and escalates bus-off conditions
- [x] **COMM-04**: Multi-cluster CAN support runs one C thread per CAN interface (CAN0/CAN1) for parallel bus operation
- [x] **COMM-05**: Modbus RTU PCS polling reads telemetry registers (0x6020–0x605C) and writes setpoints (0x500E, 0x0291) at ~500ms cycle via pymodbus async
- [x] **COMM-06**: Modbus timeout and reconnect uses configurable per-device timeouts, exponential backoff, and separate serial clients per RS485 port
- [x] **COMM-07**: Modbus CRC and exception code handling maps exception codes (01–06) to structured events and tracks CRC failures as comm quality metric
- [x] **COMM-08**: GPIO monitoring via libgpiod reads 8 DI signals using edge detection and writes state to RTDB gpio section
- [x] **COMM-09**: All comm data writes to RTDB use seqlock (single-writer-per-section) and publish on ZMQ telemetry socket with MessagePack envelope
- [x] **COMM-10**: Comm fault events pushed to logger via ZMQ PUSH socket with device ID, fault type, and timestamp
- [x] **COMM-11**: Startup device discovery polls each configured device, marks reachable/unreachable in RTDB, and completes within configurable timeout
- [x] **COMM-12**: Modbus RTU polling for BTMS, Meter, DG, and PV devices uses same pattern as PCS with device-specific register map YAML
- [x] **COMM-13**: Hybrid C+Python architecture runs CAN decode as separate C process for crash isolation, Python handles Modbus polling and lifecycle orchestration

### Safety (safety_manager)

- [x] **SAFE-01**: E-Stop dual-channel detection reads DI-6 (NO) and DI-7 (NC) via libgpiod edge events, triggers only when both confirm, flags single-channel as wiring fault
- [x] **SAFE-02**: E-Stop response asserts DO-5 (PCS stop), DO-0 (ACDB trip), DO-6 (siren), DO-4 (fault lamp) within single response cycle, all within <100ms of detection
- [x] **SAFE-03**: Fire dual-confirm requires both DI-3 (Smoke) and DI-4 (Heat) active before activating DO-1 (extinguisher) plus all E-Stop outputs
- [x] **SAFE-04**: Flood detection on DI-1 triggers PCS stop (DO-5), ACDB trip (DO-0), and siren (DO-6)
- [x] **SAFE-05**: Hardware watchdog opens /dev/watchdog and kicks every 500ms, only after completing safety scan cycle (never from timer)
- [x] **SAFE-06**: SCHED_FIFO real-time priority set at process start with mlockall(MCL_CURRENT|MCL_FUTURE) to prevent page faults
- [x] **SAFE-07**: Dedicated watchdog feed thread at higher priority than GPIO poll thread to prevent SCHED_FIFO starvation
- [x] **SAFE-08**: RTDB GPIO writes update rtdb->gpio.di[] on every edge event and rtdb->gpio.do_state[] on every output change via seqlock
- [x] **SAFE-09**: ZMQ safety events published on telemetry socket and pushed to logger with event type, timestamp, and affected channels
- [x] **SAFE-10**: Independent process lifecycle with systemd Restart=always, no runtime dependencies on other EMS services
- [x] **SAFE-11**: Graceful degradation on GPIO failure assumes worst case (E-Stop active) if libgpiod cannot open chip/line, logs critical error

### Data (data_manager)

- [x] **DATA-01**: POSIX shm creation via shm_open + ftruncate + mmap, sized from system_config.yaml topology (cluster_count, racks_per_cluster, modules_per_rack, cells_per_module)
- [x] **DATA-02**: RTDB initialization zeroes entire segment, writes magic/version/topology counts, initializes all seqlocks to 0 (even = no write in progress)
- [x] **DATA-03**: RTDB lifecycle API provides create/attach/detach/destroy for both C (libems_rtdb.so) and Python (ems_common/rtdb.py with resource_tracker.unregister() fix)
- [x] **DATA-04**: Topology validation writes actual cluster_count, racks_per_cluster etc. from config; all readers check these before iterating
- [x] **DATA-05**: ZMQ PUB/SUB telemetry fan-out binds SOCK_TELEMETRY, publishes 1Hz RTDB section snapshots as MessagePack per topic prefix
- [x] **DATA-06**: Health monitoring checks last_update_ms per RTDB section against CLOCK_MONOTONIC at 1Hz, publishes stale warnings on telemetry socket
- [x] **DATA-07**: Startup ordering via systemd After=ems-data-manager.service ensures RTDB exists before consumers attach
- [x] **DATA-08**: Periodic RTDB snapshot dumps full shared memory to disk file for post-mortem forensic analysis (configurable interval, default 60s, and on safety event)

### Logging (logger)

- [x] **LOG-01**: 1Hz Parquet telemetry subscribes to ZMQ telemetry PUB, buffers 1 second of RTDB snapshots, writes to Parquet files with PyArrow streaming writer
- [x] **LOG-02**: Parquet file rotation creates new files by configurable period (hourly default) with timestamp in filename, flushes on rotation
- [x] **LOG-03**: DuckDB SQL query interface reads Parquet files directly (no persistent database), exposed via ZMQ REQ/REP for HMI and diagnostics
- [x] **LOG-04**: JSONL structured event logging binds ZMQ PULL socket, receives events from all modules, appends to daily JSONL file with rotation
- [x] **LOG-05**: 90-day raw Parquet retention keeps all telemetry files for configurable period (default 90 days)
- [x] **LOG-06**: FIFO cleanup monitors disk via statvfs(), deletes oldest Parquet files when >80% SSD usage, never deletes JSONL before Parquet
- [x] **LOG-07**: Crash recovery uses atomic rename (write to .tmp, rename on close) for Parquet; JSONL is append-only with truncated-last-line skip on read
- [x] **LOG-08**: Parquet compression uses Snappy by default for real-time writes, reducing cell voltage array storage 5–10x
- [x] **LOG-09**: Parquet partitioning organizes files as data/{year}/{month}/{day}/telemetry_{cluster}_{hour}.parquet for efficient time-range queries

### Configuration (config_manager)

- [x] **CONF-01**: Load and validate all 14 YAML config files against JSON Schema at startup, fail fast with clear error on invalid config
- [x] **CONF-02**: Hot-reload for control_config, alarms_config, and schedule_config via inotify IN_CLOSE_WRITE with 500ms debounce, validate-then-swap semantics
- [x] **CONF-03**: Schema version validation rejects configs with mismatched schema version and provides migration guidance in error message
- [x] **CONF-04**: Config backup copies current file to config/backups/{name}.{timestamp}.yaml before applying hot-reload changes (keep last 5)
- [x] **CONF-05**: ZMQ REQ/REP config query API serves get_config(name) and get_value(name, path) requests with MessagePack responses
- [x] **CONF-06**: Deployment profile support loads profile overlay from config/profiles/ on top of defaults at startup, specified via CLI arg or environment variable
- [x] **CONF-07**: Config validation dry-run CLI command (ems-config validate <file>) returns OK or detailed validation errors for field service use
- [x] **CONF-08**: Config diff on reload includes old-vs-new diff in config_reload ZMQ event payload so subscribers know what changed

## Future Requirements

Deferred to M1.5 or later milestones. Tracked but not in current roadmap.

### Communications

- **COMM-14**: CAN frame loss rate tracking (expected vs received frames per rack per cycle) as RTDB metric
- **COMM-15**: Modbus QoS metrics (per-device response time histogram, timeout rate, CRC error rate)
- **COMM-16**: Auto-detection of CAN bitrate for field commissioning
- **COMM-17**: Graceful device hot-swap (rack added/removed without restart)
- **COMM-18**: CAN FD support (pending BMS vendor confirmation, Decision #4.2)

### Safety

- **SAFE-12**: Safety state machine with explicit transitions (NORMAL→ESTOP→RECOVERY→NORMAL) and audit trail
- **SAFE-13**: Channel discrepancy detection for E-Stop wiring fault identification
- **SAFE-14**: GPIO debounce with configurable per-DI timing (default 10–50ms)
- **SAFE-15**: Safety event black-box ring buffer in shm (64–128 entries, survives logger crashes)

### Logging

- **LOG-10**: 5-year summary retention with daily aggregates (min/max/avg per signal)
- **LOG-11**: Query result caching with LRU + TTL for repeated HMI queries
- **LOG-12**: Event severity filtering at ingestion (configurable minimum severity for JSONL)

### Configuration

- **CONF-09**: Config export/import for fleet deployment (tarball with version metadata)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| PCS vendor abstraction layer | Only one PCS vendor (V1.24). Extract abstraction in M2 when second vendor appears (Decision #21) |
| Multi-PCS master/slave | Pending site engineering decisions (Decision #7.3) |
| R5 bare-metal safety_manager | Deferred to v2+ with SIL-2 certification (Decision #4) |
| PREEMPT_RT kernel | Stock kernel ~5ms GPIO vs 100ms target = 20x headroom |
| Alarm threshold evaluation | Belongs in alarm_manager (M2), not comm layer |
| Cloud telemetry forwarding | Logger writes local only; cloud_manager forwards in M4 |
| Hot-reload for non-designated configs | system_config change requires RTDB resize = restart |
| Docker/container deployment | Hardware isolation requirements (Decision #28) |
| Real-time database engine | POSIX shm + seqlock is validated and sufficient |
| Protobuf/gRPC for IPC | MessagePack chosen for no-build-step iteration speed (Decision #13) |
