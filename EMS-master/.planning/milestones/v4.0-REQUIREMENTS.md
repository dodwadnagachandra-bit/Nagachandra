# Requirements: ReVx EMS

**Defined:** 2026-03-15
**Core Value:** Reliable, safe control of battery energy storage — safety manager protects equipment and people, control loop maintains correct power dispatch, system never loses telemetry data.

## v4.0 Requirements

Requirements for M3 — HMI & Scheduling. Each maps to roadmap phases.

### HMI Server (hmi_server)

- [x] **HMI-01**: FastAPI backend serves React frontend build as static files on configurable HTTP port (default 8080), with CORS and security headers
- [x] **HMI-02**: WebSocket endpoint streams 1Hz telemetry from ZMQ SUB (topics: system, bms.rack, pcs, gpio, meter, btms) to connected clients as JSON
- [x] **HMI-03**: REST API proxies commands to control_manager (mode_change, manual_setpoint, source_priority, fault_reset, maintenance) and alarm_manager (acknowledge) via ZMQ REQ/REP
- [x] **HMI-04**: PIN-based authentication with two tiers — operator PIN (read + basic commands) and admin PIN (full config access) — bcrypt hashed, configurable session timeout
- [x] **HMI-05**: Dashboard screen shows system overview — total SOC, active power, PCS state, control state, source priority mode, active alarms count, indicator lamp states
- [x] **HMI-06**: BMS detail screen shows per-rack SOC, voltage, current, min/max cell voltage and temperature, online status, with rack selector
- [x] **HMI-07**: PCS detail screen shows 3-phase AC voltage/current/power, DC bus, frequency, PCS state, fault codes, temperature, power setpoint
- [x] **HMI-08**: Alarm screen shows active alarm list (sortable by severity/time), alarm history via logger query API, acknowledge button for ACTIVE_UNACKED alarms
- [x] **HMI-09**: Control screen shows state machine state, source priority mode selector (DAY/NIGHT/MANUAL), manual power setpoint input, maintenance enter/exit, fault reset button
- [x] **HMI-10**: Energy screen shows charge/discharge energy totals (today, this week, this month) via logger energy_totals query, with bar chart
- [x] **HMI-11**: Settings screen (admin-only) shows system config, allows schedule editing (time windows, power curve), and config validation feedback
- [x] **HMI-12**: React frontend uses Tailwind CSS dark theme, responsive layout for 10″/15″ touch panels, Chart.js for time-series and energy charts
- [x] **HMI-13**: Frontend auto-reconnects WebSocket on disconnect with exponential backoff (1s → 30s cap), shows connection status indicator

### Scheduler (scheduler)

- [x] **SCHED-01**: Scheduler evaluates schedule_config.yaml time windows at 1Hz and sends setpoint commands to control_manager via ZMQ REQ on control_cmd socket
- [x] **SCHED-02**: Three scheduling modes: manual (no automatic dispatch), time_of_day (fixed windows), curve (96-point 15-minute intervals)
- [x] **SCHED-03**: Time-of-day mode evaluates current time against configured windows and sends charge/discharge/idle commands with configured power_kw
- [x] **SCHED-04**: Curve mode reads 96-point power array (15-min intervals), interpolates current index from system clock, sends power setpoint to control_manager
- [x] **SCHED-05**: Day/night mode switching reads day_start/night_start from schedule_config and updates control_manager source_priority via ZMQ command
- [x] **SCHED-06**: Hot-reload of schedule_config.yaml applies new windows, curve, and mode without restarting the scheduler
- [x] **SCHED-07**: Scheduler publishes current schedule state (active window, mode, next transition) on ZMQ telemetry for HMI display

## Out of Scope

| Feature | Reason |
|---------|--------|
| Cloud telemetry forwarding | M4 scope — cloud_manager handles MQTT |
| OTA firmware updates | M4 scope — ota_manager handles A/B partition |
| Diagnostics screens | M5 scope — diagnostics module provides data |
| Multi-PCS HMI views | Pending Decision #7.3 (single PCS only) |
| Mobile app | Embedded kiosk only — no mobile client |
| SSR (server-side rendering) | Not needed for embedded kiosk — static React build |
| Node.js in production | React built at deploy time, served as static files by FastAPI |
