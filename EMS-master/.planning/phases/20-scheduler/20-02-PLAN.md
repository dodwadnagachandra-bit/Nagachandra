    Internal state tracking (per CONTEXT.md locked decisions):
    - `_mode: str` -- current schedule mode ("manual", "time_of_day", "curve")
    - `_last_window_result: WindowResult | None` -- last evaluation result for change detection
    - `_last_curve_index: int | None` -- last 96-point index for change detection
    - `_last_day_night: str | None` -- last day/night mode for transition detection
    - `_schedule_owns_priority: bool` -- True when scheduler has set MANUAL source_priority (time_of_day/curve mode)
    - `_stop_event: asyncio.Event` -- graceful shutdown
    - `_tel_seq: int` -- telemetry sequence counter

    ZMQ sockets (created in __init__, env var overrides for test isolation):
    - `_req: zmq.Socket` (REQ) -> connects to SOCK_CONTROL_CMD (default) or req_endpoint
    - `_config_sub: zmq.Socket` (SUB) -> connects to SOCK_CONFIG_PUB, subscribes to TOPIC_CONFIG_RELOAD
    - `_pub: zmq.Socket` (PUB) -> binds to SOCK_SCHEDULER_PUB (default) or pub_endpoint

    Key methods:
    - `async run()` -- main 1Hz loop: poll config reload, evaluate schedule, publish telemetry, asyncio.sleep correction
    - `_evaluate_tick(now: datetime)` -- dispatch to evaluator functions based on mode, detect state changes, send commands
    - `_evaluate_day_night_tick(now: datetime)` -- always runs (even in manual mode), sends source_priority on transition
    - `_send_command(action: str, params: dict) -> bool` -- REQ with 5s timeout, recreate socket on timeout (per CONTEXT.md)
    - `_poll_config_reload()` -- SUB NOBLOCK recv, filter for name="schedule_config", re-read config from disk, reset tracking state
    - `_publish_telemetry(now: datetime)` -- PUB multipart [TOPIC_SCHEDULE, encoded envelope]
    - `cleanup()` -- close all ZMQ sockets and context
    - `stop_event` property -- expose for signal handler

    Command dispatch logic (per CONTEXT.md locked decisions):
    1. On first tick or when entering time_of_day/curve mode: send `source_priority {"mode": "manual"}` then setpoint. Set `_schedule_owns_priority = True`.
    2. On state change in time_of_day: compare new WindowResult with _last_window_result. If different, send `manual_setpoint {"power_kw": <signed>}`.
    3. On state change in curve: compare new curve index with _last_curve_index. If different, send `manual_setpoint {"power_kw": <signed>}`.
    4. When mode changes to "manual": if `_schedule_owns_priority`, evaluate current day/night and send `source_priority {"mode": "day"/"night"}`. Set `_schedule_owns_priority = False`.
    5. Day/night transitions: compare evaluate_day_night result with _last_day_night. If different AND NOT _schedule_owns_priority, send `source_priority {"mode": "day"/"night"}`.

    REQ timeout handling (per CONTEXT.md):
    - poll(5000) for reply. If timeout, log WARNING, close socket, create new REQ socket, connect to same endpoint. Return False.
    - This is critical: ZMQ REQ/REP lockstep means a stuck recv leaves the socket unusable.
