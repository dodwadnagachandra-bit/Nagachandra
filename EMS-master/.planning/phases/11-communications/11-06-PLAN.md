  <action>
Create test_integration_can.py with pytest tests that:

1. **Skip conditions:** Skip all tests if:
   - vcan kernel module not available (`modprobe vcan` fails or not root)
   - comm_manager_c binary not built (`build/src/comm_manager/c/comm_manager_c` not found)
   - /run/ems/ not available (ipc paths hardcoded in C binary)
   Use `pytest.mark.skipif` with clear skip messages.

2. **Fixtures:**
   - `vcan_interface`: Creates vcan0 via `ip link add dev vcan0 type vcan && ip link set up vcan0`, tears down after test. Requires root or CAP_NET_ADMIN.
   - `rtdb_fixture`: Creates RTDB shm with test topology (1 cluster, 2 racks), tears down after.
   - `comm_manager_c_process`: Starts comm_manager_c as subprocess with `--interface vcan0 --base-id 0x18FF0003 --clusters 1 --racks-per-cluster 2 --heartbeat-timeout-ms 900`. Kills on teardown.
   - `can_simulator`: Starts CAN simulator as subprocess sending on vcan0 for 2 racks.

3. **Tests:**
   - `test_can_decode_pack_summary`: Start simulator + comm_manager_c, wait 2s, read RTDB rack[0].pack_v -- should be non-zero (simulator sends realistic values).
   - `test_can_decode_all_racks`: Verify both rack[0] and rack[1] have non-zero last_update_ms after 3s of simulation.
   - `test_can_heartbeat_timeout`: Start comm_manager_c, send a few frames from simulator, stop simulator, wait 2s, verify rack.online == 0 in RTDB.
   - `test_can_error_frame`: Send synthetic error frame on vcan0 (CAN_ERR_FLAG | CAN_ERR_BUSOFF), verify RTDB can_health[0].bus_state == CAN_BUS_OFF.
   - `test_can_online_recovery`: Start with simulator, verify online, stop simulator (goes offline), restart simulator, verify online again.

4. Use subprocess.Popen for C process management. Use python-can library (already a dev dep) to send individual test frames when simulator isn't suitable.

5. All tests use `@pytest.mark.integration` marker for selective running.

6. Timeouts: Each test has max 10s timeout via pytest-timeout or asyncio.wait_for.
