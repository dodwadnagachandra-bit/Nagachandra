<task type="auto">
  <name>Task 1: Main entry point with RT setup, config loading, and scan loop</name>
  <files>src/safety_manager/src/main.c</files>
  <action>
Replace the stub main.c with the complete safety_manager entry point. This is the most critical file in the EMS system.

**Process startup sequence (before scan loop):**
1. Register signal handlers for SIGTERM and SIGINT (set volatile sig_atomic_t g_running = 0).
2. Call `setup_realtime(80)`:
   - `mlockall(MCL_CURRENT | MCL_FUTURE)` -- lock all memory. If fails, log WARNING and continue (non-RT mode for dev).
   - Pre-fault stack: `volatile char stack[64*1024]; memset((char*)stack, 0, sizeof(stack));`
   - `sched_setscheduler(0, SCHED_FIFO, &param)` with priority 80. If EPERM, log WARNING and continue (needs CAP_SYS_NICE).
3. Load GPIO config:
   - Try ZMQ REQ to config_manager (`EMS_SOCK_CONFIG`) with 1-second timeout: `{action: "get_config", params: {name: "gpio_config"}}`.
   - If ZMQ fails (config_manager not running), fall back to direct YAML file read from `/opt/ems/config/gpio_config.yaml` (or path from `--config` CLI arg).
   - If both fail, use compiled-in defaults (all active_high, standard pin layout). Log CRITICAL.
   - Parse active_low flags into `gpio_config_t`.
   - Note: For simplicity, the YAML fallback can use a minimal parser or just hardcode the residential profile defaults. Full libyaml parsing is not required -- the config schema is simple (8 DI + 8 DO with active_low bool each). A simple key-value scan of the YAML file is sufficient. Alternatively, skip YAML parsing entirely and use compiled-in defaults matching the residential profile, logging a WARNING that config was not loaded from config_manager.
4. Attach RTDB: `rtdb_attach()`. If NULL, retry 3 times with 1-second sleep. If still NULL, log CRITICAL but continue (safety_manager must run even without RTDB per SAFE-10 -- it just can't publish state).
5. Select GPIO backend:
   - If `--rtdb-backend` CLI arg or `EMS_GPIO_BACKEND=rtdb` env var: use `gpio_ops_rtdb` and call `rtdb_backend_init(rtdb)`.
   - Otherwise: use `gpio_ops_libgpiod`.
6. Initialize GPIO: `gpio->init(chip_path, di_offsets, 8, do_offsets, 8)`. If fails:
   - Set `state.gpio_failure = true` -- this triggers full fail-safe (all outputs asserted) per SAFE-11.
   - Continue into scan loop (will assert all safety outputs via response matrix).
7. Initialize ZMQ events: `safety_event_init()`. Non-fatal if fails.
8. Initialize ZMQ reset: `safety_reset_init()`. Non-fatal if fails.
9. Open watchdog: `watchdog_open("/dev/watchdog", 2)`. If fails (dev env), continue without.
10. Start watchdog thread: `watchdog_thread_start(wdt_fd, 81)` -- priority 81 (higher than scan at 80).
11. Log startup complete. Publish "safety_manager_started" event.

**Main scan loop (runs at SCHED_FIFO 80):**
Each iteration:
1. Read all DI via `gpio->read_di(di_raw, 8)`. If returns -1: `state.gpio_failure = true`.
2. If read succeeded: `state.gpio_failure = false; evaluate_inputs(di_raw, &gpio_cfg, &state);`
3. Poll for reset commands: `safety_reset_poll(&reset_ctx, &state, di_raw, &gpio_cfg)` (non-blocking).
4. Compute DO bitmask: `uint8_t do_mask = evaluate_response_matrix(&state);`
5. Convert bitmask to per-pin array: `do_out[i] = (do_mask >> i) & 1` for i=0..7.
6. Write DO: `gpio->write_do(do_out, 8)`.
7. Write RTDB GPIO section (if RTDB available):
   - `ems_seqlock_write_begin(&rtdb->gpio.lock);`
   - Copy di_raw[8] to rtdb->gpio.di[8], do_out[8] to rtdb->gpio.do_state[8].
   - Set rtdb->gpio.last_update_ms from CLOCK_MONOTONIC.
   - `ems_seqlock_write_end(&rtdb->gpio.lock);`
8. Publish events for DO state changes (compare with do_prev[8]). Use appropriate severity: CRITICAL for protective outputs, WARNING for advisory.
9. `memcpy(do_prev, do_out, 8);`
10. Signal watchdog: `watchdog_signal_scan_complete();`
11. Sleep 10ms: `nanosleep(&(struct timespec){0, 10000000}, NULL);`

**Shutdown sequence:**
1. Stop watchdog thread: `watchdog_thread_stop()`.
2. Close watchdog: `watchdog_close(wdt_fd)` (magic close).
3. De-assert all outputs (set all DO low) before exit.
4. Close GPIO: `gpio->close()`.
5. Close ZMQ: `safety_event_close()`, `safety_reset_close()`.
6. Detach RTDB: `rtdb_detach()`.
7. Log shutdown complete.

**CLI arguments (argparse-style with getopt_long):**
- `--config PATH` -- config file path (default: /opt/ems/config/gpio_config.yaml)
- `--chip PATH` -- GPIO chip device path (default: /dev/gpiochip0)
- `--rtdb-backend` -- use RTDB backend instead of libgpiod (for testing)
- `--no-watchdog` -- skip watchdog open (for testing)
- `--scan-interval-ms N` -- scan interval in ms (default: 10)

[Unit]
Description=EMS Safety Manager -- L1 Safety layer (RT GPIO, hardware watchdog)
Documentation=https://github.com/ReVx-Energy/EMS
# RTDB must exist before we can write GPIO state to it
After=ems-data-manager.service
# Do NOT use Requires= -- safety_manager must start even if data_manager is down (SAFE-10)
Wants=ems-data-manager.service
PartOf=ems.target

[Service]
Type=simple
ExecStart=/opt/ems/bin/safety_manager
# Restart=always (not on-failure) -- safety must ALWAYS restart (SAFE-10)
Restart=always
RestartSec=1
# Short restart delay -- safety is critical
User=ems
Group=ems
WorkingDirectory=/opt/ems
StandardOutput=journal
StandardError=journal
SyslogIdentifier=ems-safety-manager

# Real-time scheduling capabilities (SAFE-06)
AmbientCapabilities=CAP_SYS_NICE CAP_SYS_RAWIO
LimitRTPRIO=99
LimitMEMLOCK=infinity

# Watchdog integration -- systemd monitors us too
# Note: safety_manager manages /dev/watchdog directly, this is for systemd-level monitoring
# WatchdogSec=5

# Security hardening
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
NoNewPrivileges=no
# NoNewPrivileges must be no for AmbientCapabilities to work
ReadWritePaths=/run/ems /dev/shm /opt/ems/logs
# Access to GPIO device and watchdog
DeviceAllow=/dev/gpiochip0 rw
DeviceAllow=/dev/gpiochip1 rw
DeviceAllow=/dev/watchdog rw

[Install]
WantedBy=ems.target
