  <action>
Create the GPIO abstraction and response matrix -- the two core safety modules.

**gpio.h / gpio.c:**
- Define `gpio_ops_t` vtable with function pointers: `init(chip_path, di_offsets, num_di, do_offsets, num_do)`, `read_di(values, count)`, `write_do(values, count)`, `close()`.
- Define `gpio_config_t` struct holding per-pin active_low flags (bool active_low_di[8], active_low_do[8]) loaded from gpio_config.yaml at startup.
- Implement `gpio_ops_libgpiod` (real backend): use libgpiod v2 API exclusively (gpiod_chip_open, gpiod_line_settings_new, gpiod_line_config_new, gpiod_chip_request_lines, gpiod_line_request_get_values/set_values). NOT v1 API. Separate line requests for DI (input) and DO (output). Consumer string "ems-safety-manager".
- Implement `gpio_ops_rtdb` (test backend): reads DI from RTDB gpio.di[] array, writes DO to RTDB gpio.do_state[] array. This lets tests stimulate inputs via shared memory without hardware. Requires an `rtdb_backend_init(ems_rtdb_t *rtdb)` function to set the RTDB pointer.
- `read_di` returns raw values. Active-low inversion is applied in response_matrix (evaluate_inputs), not in the GPIO layer, so the RTDB backend correctly stores raw values.
- On libgpiod `gpiod_chip_open` failure, return -1 (caller handles fail-safe). On individual `gpiod_line_request_get_values` failure, return -1.
- `write_do` writes individual pins. If a single pin write fails, log error but continue writing other pins (DO write failures never block other outputs per CONTEXT.md). Return count of failed writes.

**response_matrix.h / response_matrix.c:**
- Define `safety_state_t` struct: `bool estop_active, fire_active, flood_active, acdb_loss, door_open, gpio_failure, estop_discrepancy` plus `bool estop_latched, fire_latched, flood_latched` for manual-reset latch tracking.
- Define DO bitmask constants: `DO_ACDB_TRIP (1<<0)`, `DO_EXTINGUISHER (1<<1)`, `DO_WARNING_LAMP (1<<2)`, `DO_RUNNING_LAMP (1<<3)`, `DO_FAULT_LAMP (1<<4)`, `DO_PCS_STOP (1<<5)`, `DO_SIREN (1<<6)`. DO-7 is never asserted.
- Define `PROTECTIVE_OUTPUTS = (DO_ACDB_TRIP | DO_EXTINGUISHER | DO_PCS_STOP | DO_SIREN)`.
- Implement `evaluate_inputs(const uint8_t *di_raw, const gpio_config_t *config, safety_state_t *state)`:
  - Apply active_low inversion per pin from config: `logical = active_low ? !raw : raw`
  - E-Stop: DI-6 (NO, logical high=pressed) AND DI-7 (NC, logical high=pressed after inversion). Both true = E-Stop confirmed, set `estop_active=true, estop_latched=true`. DI-6 XOR DI-7 = wiring discrepancy, set `estop_discrepancy=true`, log CRITICAL, do NOT trigger E-Stop response.
  - Fire: DI-3 (Smoke) AND DI-4 (Heat) both logical high = fire confirmed, set `fire_active=true, fire_latched=true`. Single sensor alone sets `door_open`-style warning flag (use a `fire_single_sensor` bool for warning lamp).
  - Flood: DI-1 logical high = `flood_active=true, flood_latched=true`.
  - ACDB feedback: DI-0 logical low (loss of signal) = `acdb_loss=true`. Auto-recovers when DI-0 goes high.
  - Door: DI-2 logical high (after active_low inversion: low=open becomes high) = `door_open=true`. Auto-recovers.
  - DI-5 spare: read and store, trigger nothing.
  - Latched states (estop, fire, flood) stay true even when inputs clear -- only cleared by `safety_reset()`.
- Implement `evaluate_response_matrix(const safety_state_t *state)` returning uint8_t DO bitmask:
  - Exact mapping from CONTEXT.md response matrix table (see <interfaces> above).
  - Running lamp (DO-3) ON only when no protective outputs active (IEC 60073: green+red prohibited).
  - Fault lamp (DO-4) ON when any protective output asserted.
  - Warning and Fault CAN coexist.
  - gpio_failure asserts ALL safety outputs (worst case).
- Implement `safety_reset(safety_state_t *state, const uint8_t *di_raw, const gpio_config_t *config)`:
  - Validates that triggering inputs have actually cleared before accepting reset.
  - E-Stop reset: only if DI-6 and DI-7 both in normal state. Clears estop_latched.
  - Fire reset: only if DI-3 and DI-4 both inactive. Clears fire_latched.
  - Flood reset: only if DI-1 inactive. Clears flood_latched.
  - Returns 0 on success, -1 if inputs still active (reject reset).
