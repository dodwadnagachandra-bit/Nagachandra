  <action>
    1. **ws.py** — Create the WebSocket module with two components:

       **ClientManager class:**
       - `clients: set[asyncio.Queue]` — set of per-client queues
       - `add_client() -> asyncio.Queue` — creates Queue(maxsize=100), adds to set, returns it
       - `remove_client(queue: asyncio.Queue) -> None` — removes from set
       - `broadcast(message: dict) -> None` — for each queue in clients, `queue.put_nowait(message)`. If `asyncio.QueueFull`, call `queue.get_nowait()` to drop oldest, then `queue.put_nowait(message)`.

       **telemetry_bridge(zmq_ctx, client_manager, socket_path) async function:**
       - Creates a `zmq.asyncio.Socket` (SUB type) from the provided zmq_ctx. NOTE: For the SUB bridge, use `zmq.asyncio.Context` (not plain zmq.Context) so that `recv_multipart` is truly async.
       - Subscribes to all topics: `TOPIC_BMS_RACK`, `TOPIC_PCS`, `TOPIC_GPIO`, `TOPIC_METER`, `TOPIC_BTMS`, `TOPIC_SYSTEM`.
       - Connects to socket_path.
       - Loop: `parts = await sub.recv_multipart()`, decode topic from `parts[0].decode("utf-8")`, decode envelope from `decode_telemetry(parts[1])`, construct JSON message `{"topic": envelope["topic"], "data": envelope["payload"], "ts": envelope["ts"]}`, call `client_manager.broadcast(message)`.
       - On CancelledError: close socket, return.

       **WebSocket endpoint (/ws/telemetry):**
       - Create APIRouter or add route directly.
       - On connect: `await websocket.accept()`, get client_manager from `websocket.app.state.client_manager`, `queue = client_manager.add_client()`.
       - Loop: `message = await queue.get()`, `await websocket.send_json(message)`.
       - On WebSocketDisconnect or any exception: `client_manager.remove_client(queue)`, return.
       - Wrap the send loop in try/except for WebSocketDisconnect.

    2. **app.py** — Update lifespan:
       - Create `ClientManager` instance: `app.state.client_manager = ClientManager()`.
       - Use `zmq.asyncio.Context()` instead of `zmq.Context()` for the ZMQ context (zmq.asyncio.Context is a subclass and works for both async and sync operations, or keep a separate async context for SUB if needed).
       - Start telemetry bridge as background task: `bridge_task = asyncio.create_task(telemetry_bridge(app.state.zmq_ctx, app.state.client_manager, SOCK_TELEMETRY))`.
       - On shutdown: cancel bridge_task, await it (suppress CancelledError), term zmq_ctx.
       - Include WebSocket router.
       - Allow the socket_path to be overridden via config or app.state for testing (so tests can use tcp:// instead of ipc://).

    3. **conftest.py** — Add WebSocket test fixtures:
       - `mock_zmq_pub` fixture: Creates a ZMQ PUB socket on `tcp://127.0.0.1` (bind to random port). Provides a `publish(topic: str, payload: dict)` helper that sends multipart `[topic.encode(), encode_telemetry(ts, seq, "test", topic, payload)]`. Yields (address, publish_fn). Closes on teardown.
       - Update `test_app` fixture to pass the mock PUB address as the telemetry socket path so the bridge connects to the test PUB instead of the production ipc:// path.
       - 50ms sleep after connect for ZMQ TCP handshake (established project pattern).

    4. **test_ws.py** — Tests using Starlette TestClient's `websocket_connect`:

       - Test single client receives a published message.
       - Test two clients both receive same message.
       - Test message format matches `{topic, data, ts}`.
       - Test client disconnect doesn't crash bridge (connect, disconnect, publish again, connect new client, verify new client works).
       - Test queue overflow: publish 101 messages rapidly, verify client receives messages and the oldest are dropped (client gets 100 or fewer, with the most recent ones present).
