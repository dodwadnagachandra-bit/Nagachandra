```python
async def zmq_command(socket_path: str, action: str, params: dict) -> dict:
    """Send ZMQ REQ, return decoded response. Uses run_in_executor. 5s timeout. Raises HTTPException(504) on timeout."""

async def require_auth(request: Request) -> dict:
    """Returns {"level": "operator"|"admin", "token": str}. Raises 401."""

async def require_admin(auth: dict = Depends(require_auth)) -> dict:
    """Raises 403 if not admin level."""
```

    1. **conftest.py** — Add ZMQ mock fixtures:
       - `mock_zmq_control_rep` fixture: Creates a ZMQ REP socket on `tcp://127.0.0.1` (bind to random port). Receives command requests, decodes with `decode_command_request`, and returns canned success responses via `encode_command_response("ok", {"accepted": True})`. Runs in a background thread. Yields the bound address. Closes on teardown.
       - `mock_zmq_alarm_rep` fixture: Same pattern for alarm commands. Returns different canned responses: get_active_alarms returns `{"alarms": []}`, acknowledge returns `{"alarm_id": "ALM-001", "from_state": "active", "to_state": "acked"}`, get_alarm_config returns `{"rules": []}`.
       - `auth_headers` fixture: Logs in via POST /api/auth/login with operator PIN, returns dict `{"Authorization": f"Bearer {token}"}`.
       - `admin_auth_headers` fixture: Same but with admin PIN.
       - Override `zmq_command` in deps.py to use tcp:// test endpoints instead of ipc:// production paths. This can be done by having the app factory accept an optional `zmq_overrides: dict[str, str]` mapping from ipc:// paths to tcp:// test addresses, or by monkeypatching the socket paths in tests.

    2. **control.py** — Create APIRouter with prefix="/api/control", tag="control". All endpoints require `require_auth` dependency except maintenance which requires `require_admin`:
       - POST `/mode` — Accepts `ModeChangeRequest`. Calls `zmq_command(SOCK_CONTROL_CMD, "mode_change", {"target_state": body.target_state})`. Returns the ZMQ response as JSON.
       - POST `/setpoint` — Accepts `ManualSetpointRequest`. Action: "manual_setpoint", params: {"power_kw": body.power_kw}.
       - POST `/priority` — Accepts `SourcePriorityRequest`. Action: "source_priority", params: {"mode": body.mode}.
       - POST `/fault-reset` — No request body. Action: "fault_reset", params: {}.
       - POST `/maintenance` — Accepts `MaintenanceRequest`, requires `require_admin`. Action: "maintenance_enter" or "maintenance_exit" based on body.action.

       Each endpoint: call `zmq_command`, check response status. If status == "ok", return 200 with result. If status == "error", return 400 with error_msg.

    3. **alarm.py** — Create APIRouter with prefix="/api/alarm", tag="alarm". All endpoints require `require_auth`:
       - POST `/acknowledge` — Accepts `AcknowledgeRequest`. Action: "acknowledge", params: {"alarm_id": body.alarm_id}.
       - GET `/active` — No params. Action: "get_active_alarms", params: {}.
       - GET `/config` — No params. Action: "get_alarm_config", params: {}.

    4. **app.py** — Include control and alarm routers in `create_app`.

    5. **test_control.py** — Tests for all 5 control endpoints plus auth and timeout cases.
    6. **test_alarm.py** — Tests for all 3 alarm endpoints plus auth and timeout cases.

    For ZMQ test mocking approach: The simplest pattern is to monkeypatch `deps.zmq_command` as an async function that returns canned responses. This avoids needing real ZMQ sockets in tests. For one or two integration tests, use real tcp:// ZMQ REP sockets in background threads to verify the actual ZMQ flow end-to-end.
