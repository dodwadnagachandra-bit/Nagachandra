<objective>
GPIO test harness that simulates all 8 DI + 8 DO safety signals for safety_manager testing without physical wiring.

Purpose: SIM-05 requires a GPIO mock so safety_manager DI/DO logic (M1) can be developed and tested on any dev workstation. This harness injects DI values into the RTDB shared memory `ems_gpio_t` struct and reads back DO values, with an optional gpio-sim kernel module backend for realistic libgpiod testing.

Output: Python package at `tools/simulators/gpio_harness/` (CLI + importable), pytest test suite, Makefile target.
</objective>

       - `GpioSimBackend(GpioBackend)` that creates a virtual GPIO chip via `/sys/kernel/config/gpio-sim/` configfs.
       - Constructor: `chip_name: str = "ems-gpio"`, `num_lines: int = 16` (DI 0-7 on lines 0-7, DO 8-15 on lines 8-15).
       - `setup()`: mkdir device dir, mkdir bank0, write num_lines, create line dirs with names from gpio_config.yaml, write "1" to live, read chip_name from bank0/chip_name, locate sysfs path at `/sys/devices/platform/gpio-sim.*/`.
       - `set_di(pin, value)`: Write "pull-up" (value=1) or "pull-down" (value=0) to `sysfs_chip/sim_gpio{pin}/pull`.
       - `get_di(pin)`: Read `sysfs_chip/sim_gpio{pin}/value`.
       - `get_do(pin)`: Read `sysfs_chip/sim_gpio{pin + 8}/value` (DO offset by 8).
       - `set_di_multi(values)`: Write all pull values (no seqlock needed — gpio-sim is sysfs).
       - `teardown()`: Write "0" to live, rmdir line dirs (reverse order), rmdir bank, rmdir device. Use try/except for cleanup robustness.
       - `close()`: Calls teardown().
       - Register atexit handler in constructor to ensure teardown on abnormal exit.
