**New method `_poll_alarm_events(self) -> str | None`:**
Drain alarm SUB socket NOBLOCK. Return highest severity seen this tick. Use severity_rank dict: {"warning": 0, "action": 1, "protection": 2}. Decode with `msgpack.unpackb(body, raw=False)` — NOT `decode_event()` (alarm PUB is raw msgpack per RESEARCH.md Pitfall 1). Topic frame received first, then body frame.

**New method `_poll_config_reload(self) -> None`:**
Drain config reload SUB socket NOBLOCK. For each message received:
1. Receive multipart [topic_frame, body_frame]
2. Decode body with `msgpack.unpackb(body_frame, raw=False)`
3. Check `data["name"]` — only handle `"control_config"`
4. Re-read and validate config from disk: call `load_control_config(self._config_path)`
5. On success: `self._config = new_config`, `self._intelligence.update_config(new_config)`, log info
6. On ValueError/FileNotFoundError: log error, keep old config

Why re-read from disk instead of using the config dict from the event payload: the event carries the full config, but re-reading ensures we go through the same validation path (load_control_config with schema validation). The event is the notification trigger; disk is the source of truth.
