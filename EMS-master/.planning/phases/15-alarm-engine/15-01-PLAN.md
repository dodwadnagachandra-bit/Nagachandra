<objective>
Create the alarm_manager foundation: config loader, RTDB signal resolver, and AlarmInstance dataclass.

Purpose: These are the data contracts and resolution layer that the evaluator (Plan 02) and loop (Plan 03) build on. Config loading validates the 9 alarm rules from alarms_config.yaml. The signal resolver maps dotted paths (e.g., "bms.cell_voltage_max") to RTDB field reads using a pre-built dictionary. AlarmInstance is the per-rule lifecycle dataclass with pre-computed clear thresholds.

Output: config.py, resolver.py, evaluator.py (dataclass + constants only), test_config.py, test_resolver.py
</objective>

  <action>
    **config.py:** Create `load_alarm_config(path: Path, schema_path: Path | None = None) -> dict[str, Any]` following the exact pattern from `ems_control_manager/config.py`:
    - Load YAML with `yaml.safe_load`
    - If `schema_path` is None, derive from `path.parent.parent / "schemas" / "alarms_config.schema.json"` (following control_config pattern)
    - Validate with `jsonschema.Draft202012Validator`
    - Raise `ValueError` on validation failure (not `jsonschema.ValidationError`) per project convention from 14-01
    - Raise `FileNotFoundError` if config or schema file missing

    **resolver.py:** Create `SignalResolver` class:
    - `__init__(self)`: builds the resolver dict mapping 7 signal paths to callables
    - Each callable takes an `EmsRtdb` and returns `float | None`
    - BMS aggregate paths iterate `clusters[c].racks[r]` for c in range(MAX_CLUSTERS), r in range(MAX_RACKS_PER_CLUSTER), filtering `rack.online != 0`
    - `bms.cell_voltage_max` -> `max(rack.max_cell_v for online racks)` or None
    - `bms.cell_voltage_min` -> `min(rack.min_cell_v for online racks)` or None
    - `bms.cell_temp_max` -> `max(rack.max_cell_t for online racks)` or None
    - `bms.cell_temp_min` -> `min(rack.min_cell_t for online racks)` or None
    - `bms.soc_pct` -> `mean(rack.pack_soc for online racks)` or None
    - `bms.bus_voltage_v` -> `rtdb.pcs.dc_voltage`
    - `pcs.internal_temp_c` -> `rtdb.pcs.temperature`
    - `resolve(self, signal_path: str, rtdb: EmsRtdb) -> float | None`: looks up path in dict, calls resolver, returns None for unknown paths
    - `resolve_all(self, signal_paths: list[str], rtdb: EmsRtdb) -> dict[str, float | None]`: resolve all paths in one call, caching per tick
    - `validate_paths(self, paths: list[str]) -> list[str]`: returns list of unknown paths (for startup validation)

    **Tests:** Use real ctypes structs in process memory (MockRtdb pattern from Phase 14). For resolver tests, create EmsRtdb instance, set rack fields directly. No RTDB shared memory needed — ctypes structs work identically in process memory.

    **Lifecycle state constants** (plain strings, not Enum — matches IEC 62682 names):
    ```python
    STATE_NORMAL: str = "NORMAL"
    STATE_ACTIVE_UNACKED: str = "ACTIVE_UNACKED"
    STATE_ACTIVE_ACKED: str = "ACTIVE_ACKED"
    STATE_CLEARED_UNACKED: str = "CLEARED_UNACKED"
    STATE_RTN: str = "RTN"
    ```

    **AlarmInstance dataclass:**
    ```python
    @dataclasses.dataclass
    class AlarmInstance:
        alarm_id: str
        signal: str
        severity: str  # "warning" | "action" | "protection"
        high_threshold: float | None
        low_threshold: float | None
        hysteresis_pct: float
        delay_ms: int
        enabled: bool
        # Pre-computed clear thresholds (set in __post_init__)
        high_clear: float | None = None
        low_clear: float | None = None
        # Runtime state
        state: str = STATE_NORMAL
        exceeded_since_ms: float | None = None
        current_value: float = 0.0
        # Timestamps (wall-clock ms, 0 = not yet set)
        activated_at: int = 0
        acknowledged_at: int = 0
        cleared_at: int = 0
        rtn_at: int = 0
    ```

    **__post_init__:** Pre-compute `high_clear` and `low_clear` from hysteresis:
    - `high_clear = high_threshold - abs(high_threshold) * hysteresis_pct / 100.0` if high_threshold is not None
    - `low_clear = low_threshold + abs(low_threshold) * hysteresis_pct / 100.0` if low_threshold is not None

    **Helper function:** `build_alarm_instances(config: dict) -> dict[str, AlarmInstance]`:
    - Takes the loaded config dict (from load_alarm_config)
    - For each rule in config["rules"], create an AlarmInstance
    - Use config["defaults"]["hysteresis_pct"] and config["defaults"]["delay_ms"] as fallbacks if not specified per-rule
    - Returns dict keyed by alarm_id
    - Log WARNING for any rule with neither high_threshold nor low_threshold

    Do NOT add evaluation methods yet — that is Plan 02 scope (TDD).
