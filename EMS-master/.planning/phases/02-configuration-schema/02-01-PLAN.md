Create 3 JSON Schema files and their corresponding YAML config files. Each schema MUST use:
- `"$schema": "https://json-schema.org/draft/2020-12/schema"`
- `"$id": "https://revx-energy.com/ems/schemas/{config_name}"`
- `"additionalProperties": false` at every object level (LOCKED decision)
- `x-unit` metadata on all numeric fields
- Type annotations and descriptions on every property

**A. `config/schemas/system_config.schema.json`:**

Top-level required sections: `system`, `topology`

`system` object (additionalProperties: false):
- `site_id` (string, required) — unique site identifier
- `site_name` (string, required) — human-readable site name
- `firmware_version` (string) — EMS firmware version
- `model` (string, enum: ["residential", "commercial", "container"]) — deployment scale tier

`topology` object (additionalProperties: false, all required):
- `cluster_count` (integer, min 1, max 8, x-unit: "count") — battery clusters
- `racks_per_cluster` (integer, min 1, max 16, x-unit: "count") — BMU racks per cluster
- `modules_per_rack` (integer, min 3, max 20, x-unit: "count") — LMU modules per rack
- `cells_per_module` (integer, min 16, max 108, x-unit: "count") — series cells per module
- `temps_per_module` (integer, min 4, max 40, x-unit: "count") — temperature sensors per module

**B. `config/schemas/bms_config.schema.json`:**

Top-level required sections: `can`, `timing`

`can` object (additionalProperties: false):
- `interface` (string, required) — CAN interface name (e.g., "can0", "vcan0")
- `bitrate` (integer, enum: [250000, 500000, 1000000], required, x-unit: "bps") — CAN bus bitrate
- `fd_enabled` (boolean) — CAN FD mode
- `dbc_path` (string, required) — path to DBC file for signal decoding
- `base_id` (integer, required) — base CAN arbitration ID (e.g., 0x98FF0003)

`timing` object (additionalProperties: false):
- `fast_cycle_ms` (integer, min 100, max 1000, required, x-unit: "ms") — fast message cycle (default 300ms)
- `slow_cycle_ms` (integer, min 1000, max 5000, required, x-unit: "ms") — slow message cycle (default 2000ms)
- `timeout_ms` (integer, min 1000, max 30000, required, x-unit: "ms") — communication timeout

**C. `config/schemas/pcs_config.schema.json`:**

This schema demonstrates the if/then RTU/TCP conditional pattern (LOCKED decision).

Top-level required sections: `connection`, `registers`, `timing`

`connection` object (additionalProperties: false):
- `protocol` (string, enum: ["rtu", "tcp"], required)
- `slave_id` (integer, min 1, max 247, required)
- RTU-specific: `device` (string), `baud_rate` (integer, enum: [9600, 19200, 38400, 115200], x-unit: "bps"), `parity` (string, enum: ["N", "E", "O"]), `stopbits` (integer, enum: [1, 2])
- TCP-specific: `host` (string), `port` (integer, min 1, max 65535)
- Use `if/then/else`: if protocol=="rtu" then require device, baud_rate, parity; else require host, port

`registers` object (additionalProperties: false):
- `power_setpoint` (integer, required, x-unit: "register") — 0x500E default
- `on_off_control` (integer, required, x-unit: "register") — 0x0291 default
- `voltage_read` (integer, required, x-unit: "register")
- `current_read` (integer, required, x-unit: "register")
- `frequency_read` (integer, required, x-unit: "register")

`timing` object (additionalProperties: false):
- `poll_interval_ms` (integer, min 100, max 5000, required, x-unit: "ms")
- `timeout_ms` (integer, min 500, max 10000, required, x-unit: "ms")
- `retry_count` (integer, min 0, max 10, required, x-unit: "count")
