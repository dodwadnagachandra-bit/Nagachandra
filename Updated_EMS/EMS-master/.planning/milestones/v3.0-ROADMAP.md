## Overview

M2 builds the control_manager (1Hz state machine, power dispatch, source priority) and alarm_manager (IEC 62682 3-tier alarm evaluation, lifecycle management, protection actions) that close the loop from telemetry to PCS control. These modules sit at L4 (Application Logic) and consume the L1-L3 infrastructure built in M1.

## Key Accomplishments

1. **control_manager** — 8-state machine (INIT→IDLE→STANDBY→CHARGING/DISCHARGING→FAULT→EMERGENCY→MAINTENANCE), 1Hz async loop, PCS command dispatch via RTDB (setpoint 0x500E + on/off 0x0291 + fault_reset 0x5064), 6-command ZMQ API (mode_change, manual_setpoint, source_priority, fault_reset, maintenance_enter/exit), non-blocking PCS sequencing with 10s timers and internal sub-states
2. **alarm_manager** — IEC 62682 5-state lifecycle engine (NORMAL→ACTIVE_UNACKED→ACTIVE_ACKED→CLEARED_UNACKED→RTN), 9 configurable alarm rules from alarms_config.yaml, signal resolver with offline rack exclusion, hysteresis + delay filtering, ZMQ PUSH/PUB events, REQ/REP query API (get_active_alarms, acknowledge, get_alarm_config)
3. **Control intelligence** — Source priority dispatch (DAY/NIGHT/MANUAL waterfall), SOC charge/discharge cutoff limits, 3-zone temperature derating (BMS cell high 40°C/50°C, BMS cell low 5°C/0°C, PCS 65°C/80°C), configurable power ramping (kW/s), safety interlock checks
4. **Alarm-to-control protection** — PUB/SUB from alarm_manager to control_manager (non-blocking), protection severity triggers FAULT state, action severity reduces power 50% with 60s cooldown, oscillation prevention
5. **Config hot-reload** — config_manager PUB broadcast on SOCK_CONFIG_PUB, both control_manager and alarm_manager subscribe via ZMQ SUB, atomic config swap preserving alarm lifecycle state
6. **Integration validated** — E2E protection flow (BMS voltage drop → alarm → control FAULT → PCS stop), 5 dispatch scenarios, crash recovery for both modules, 4 hot-reload scenarios

## Key Decisions Made

- PCS commands go through RTDB (single-writer-per-section preserved), not direct Modbus
- pcs_command + pcs_command_seq for dedup; active_derating_pct added to ems_system_t
- CHARGING↔DISCHARGING forbidden — must pass through STANDBY (DC bus transient prevention)
- FAULT = PCS-reported (recoverable), EMERGENCY = safety-triggered (not recoverable by control)
- Alarm-to-control uses PUB/SUB (not REQ/REP) — non-blocking, avoids deadlock
- 60-second cooldown after protection alarm prevents oscillation
- IEC 62682 5-state lifecycle (NORMAL, ACTIVE_UNACKED, ACTIVE_ACKED, CLEARED_UNACKED, RTN)
- Piecewise linear derating with 3 thermal zones, most restrictive wins
- Config hot-reload via config_manager PUB → modules SUB on SOCK_CONFIG_PUB
