## Overview

M1 builds the 5 core L1–L3 modules that all higher layers depend on: config_manager, data_manager, safety_manager, comm_manager, and logger. These modules handle configuration validation, real-time data sharing via POSIX shared memory, safety-critical GPIO response, CAN/Modbus device communication, and telemetry/event persistence.

## Key Accomplishments

1. **config_manager** — 14 YAML config files with JSON Schema validation, hot-reload (inotify + 500ms debounce), profile overlays, ZMQ REQ/REP query API, CLI validation tool (`ems-config validate`)
2. **data_manager** — POSIX shared memory RTDB lifecycle (C library libems_rtdb.so + Python ctypes), 1Hz ZMQ telemetry publisher, health monitoring (stale section detection), periodic snapshots (atomic write + pruning)
3. **safety_manager** — Independent C process with <100ms GPIO response, dual-channel E-Stop (DI-6+DI-7), fire dual-confirm (DI-3+DI-4), flood/ACDB/door handling, hardware watchdog (/dev/watchdog), SCHED_FIFO RT priority 80, response matrix with manual latch recovery via ZMQ, indicator lamp behavior (IEC 60073)
4. **comm_manager** — Hybrid C+Python: CAN DBC decode (10 message types, heartbeat monitoring, error frames, per-interface health) as independent C process + Modbus RTU polling (PCS, BTMS, Meter, DG, PV) with per-port async tasks, priority ordering, exponential backoff, and startup discovery
5. **logger** — Parquet 1Hz telemetry (Snappy compression, hourly rotation, per-cluster + system files), JSONL structured events (daily rotation, crash recovery), DuckDB 6-query-type API via ZMQ REQ/REP, three-tier FIFO retention cleanup (90-day Parquet, 180-day JSONL, survival mode)
6. **Integration & fixes** — Full systemd startup ordering, crash recovery (SIGKILL/SIGTERM all modules), E2E pipeline validation (simulators → RTDB → ZMQ → Parquet → DuckDB), performance metrics under load, ZMQ framing convention alignment (C/Python boundary)

## Key Decisions Made

- Length-prefixed framing removed — C matches Python: PUB=[topic|body], PUSH=[body]
- HealthMonitor accepts shared PUB socket via constructor injection (no double-bind)
- safety_manager uses compiled-in defaults (no config_manager dependency)
- comm_manager_c and comm_manager are fully independent systemd services
- Logger uses predefined query types only (no free-form SQL)
- Three-tier FIFO: expired Parquet → expired JSONL → within-retention oldest-first
