## Overview

M3 builds the hmi_server (FastAPI backend with WebSocket telemetry, REST command proxy, PIN auth) and 7-screen React frontend (Dashboard, BMS, PCS, Alarms, Control, Energy, Settings) plus the scheduler (time-of-day windows, 96-point power curves, day/night mode switching). These modules sit at L4/L5 and give operators visibility and control over the BESS.

## Key Accomplishments

1. **HMI Backend** — FastAPI serves React build as static files, WebSocket bridges ZMQ PUB telemetry to JSON clients (per-client asyncio.Queue), REST proxies commands to control/alarm/logger ZMQ APIs, PIN-based auth with bcrypt (operator/admin tiers, session tokens, 30-min timeout)
2. **HMI Frontend** — 7 React screens: Dashboard (SOC gauge, power bar, alarm count), BMS (rack selector, cell ranges), PCS (AC/DC telemetry, faults), Alarms (sortable table, ACK, history), Control (state machine, mode selector, source priority DAY/NIGHT/MANUAL, setpoint keypad, maintenance), Energy (totals with bar chart), Settings (admin-only schedule editor). Tailwind v4 dark theme, responsive 10″/15″, Chart.js with animation disabled, WebSocket auto-reconnect (1s→30s backoff)
3. **Scheduler** — 3 modes (manual, time_of_day, curve), 96-point power curves at 15-min intervals, day/night source priority switching, hot-reload via SOCK_CONFIG_PUB subscription, ZMQ REQ commands to control_manager
4. **Integration** — E2E command flow (REST→ZMQ→control→RTDB→PCS), telemetry flow (simulator→RTDB→ZMQ→WebSocket→React), schedule-to-dispatch flow, WebSocket reconnection after server kill, crash recovery for both modules

## Key Decisions Made

- WebSocket streams JSON (not MessagePack) — native browser parsing
- Per-client asyncio.Queue with max 100 messages, drop oldest on overflow
- Opaque bearer tokens (not JWT) — single-server embedded kiosk
- Tab-based sidebar navigation, 44×44px touch targets, no hover states
- React Context + useReducer for state (no Redux)
- Chart.js animation disabled for ARM performance
- Scheduler uses ZMQ REQ on control_cmd (same API as HMI) — no separate path
- Schedule sends commands on state change only (not every tick)
- Day/night switching independent of schedule mode
