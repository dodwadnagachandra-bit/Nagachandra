# Requirements: ReVx EMS

**Defined:** 2026-03-15
**Core Value:** Reliable, safe control of battery energy storage — safety manager protects equipment and people, control loop maintains correct power dispatch, system never loses telemetry data.

## v5.0 Requirements

Requirements for M4 — Cloud & OTA. Each maps to roadmap phases.

### Cloud Manager (cloud_manager)

- [x] **CLOUD-01**: MQTT/TLS client connects to configured broker (port 8883) with mTLS authentication (CA cert, client cert, client key) and automatic reconnection with exponential backoff
- [x] **CLOUD-02**: Telemetry forwarding subscribes to ZMQ PUB telemetry, downsamples from 1Hz to configurable interval (10-60s per profile), and publishes to MQTT topic `{prefix}/telemetry` as JSON
- [x] **CLOUD-03**: Event forwarding subscribes to ZMQ PUB events (alarm, state_change, comm_fault) and publishes to MQTT topic `{prefix}/events` with QoS 1 (at-least-once delivery)
- [x] **CLOUD-04**: Offline buffer stores telemetry and events to local disk (SSD) when MQTT connection is lost, with configurable retention (max_hours, max_mb per profile)
- [x] **CLOUD-05**: Buffer replay drains offline buffer FIFO when MQTT connection is restored, throttled to prevent broker overload, with progress tracking
- [x] **CLOUD-06**: Remote command reception subscribes to MQTT topic `{prefix}/commands` and forwards valid commands to control_manager or alarm_manager via ZMQ REQ
- [x] **CLOUD-07**: Heartbeat publishes device status (online, uptime, version, connectivity quality) to `{prefix}/status` at configurable interval (default 60s)
- [x] **CLOUD-08**: Connection status published on ZMQ telemetry (topic: cloud) for HMI display — connected/disconnected/reconnecting with broker hostname and latency

### OTA Manager (ota_manager)

- [x] **OTA-01**: Firmware download receives update packages via MQTT topic `{prefix}/ota/package` or HTTP URL, stores to staging partition with integrity check (SHA-256)
- [x] **OTA-02**: Ed25519 signature verification validates package signature against embedded public key before applying any update
- [x] **OTA-03**: A/B partition management maintains two system partitions — active and standby. Updates are applied to standby, then boot flag is swapped on success
- [x] **OTA-04**: Automatic rollback monitors health after boot swap — if the new version fails health check within configurable timeout (default 300s), reverts to previous partition
- [x] **OTA-05**: Update status published on ZMQ telemetry (topic: ota) for HMI display — idle/downloading/verifying/applying/rebooting/rolled_back
- [x] **OTA-06**: Version tracking maintains current and previous firmware versions in RTDB, queryable via ZMQ REQ/REP

### OTA Manager

- **OTA-08**: BMS/PCS firmware forwarding (update downstream devices via CAN/Modbus — pending Decision #10.4)
- **OTA-09**: Scheduled update windows (apply updates only during idle periods)
