Create 11 JSON Schema files. ALL schemas MUST use:
- `"$schema": "https://json-schema.org/draft/2020-12/schema"`
- `"$id": "https://revx-energy.com/ems/schemas/{config_name}"`
- `"additionalProperties": false` at every object level
- `x-unit` metadata on all numeric fields
- Descriptions on all properties

Follow the patterns established in 02-01-SUMMARY.md (especially the if/then pattern from pcs_config for Modbus devices).

**GROUP A: Modbus device schemas** (btms, meter, dg, pv)
All 4 follow the same pattern as pcs_config — they have `connection`, `registers`, `timing` sections with the if/then RTU/TCP conditional on connection.protocol.

`btms_config.schema.json`:
- `connection`: Same if/then RTU/TCP pattern as pcs_config. Required: protocol, slave_id.
- `device`: object with `mode` (enum: ["liquid", "air"]), `setpoint_temp_c` (number, min 15, max 35, x-unit "°C")
- `timing`: `poll_interval_ms` (int, 500-5000, x-unit "ms"), `timeout_ms` (int, 500-10000, x-unit "ms")

`meter_config.schema.json`:
- `connection`: Same if/then RTU/TCP pattern. Required: protocol, slave_id.
- `device`: object with `model` (enum: ["acrel", "schneider", "abb", "generic"]), `ct_ratio` (number, min 1, x-unit "ratio")
- `timing`: Same poll_interval_ms + timeout_ms pattern

`dg_config.schema.json`:
- `connection`: Same if/then RTU/TCP pattern. Required: protocol, slave_id.
- `generator`: object with `rated_power_kw` (number, min 1, x-unit "kW"), `fuel_type` (enum: ["diesel", "gas"]), `auto_start` (boolean)
- `timing`: Same poll_interval_ms + timeout_ms pattern

`pv_config.schema.json`:
- `connection`: Same if/then RTU/TCP pattern. Required: protocol, slave_id.
- `inverter`: object with `rated_power_kw` (number, min 1, x-unit "kW"), `mppt_count` (integer, min 1, max 12, x-unit "count")
- `timing`: Same poll_interval_ms + timeout_ms pattern

**GROUP B: Hot-reloadable application schemas** (control, alarms, schedule)
These 3 schemas MUST have `"x-hot-reload": true` at the schema root level (LOCKED decision).

`control_config.schema.json`:
- Root: `x-hot-reload: true`
- `soc_limits`: object with `charge_cutoff_pct` (number, 80-100, x-unit "%", x-mutable: true), `discharge_cutoff_pct` (number, 0-30, x-unit "%", x-mutable: true)
- `power_limits`: object with `max_charge_kw` (number, min 0, x-unit "kW", x-mutable: true), `max_discharge_kw` (number, min 0, x-unit "kW", x-mutable: true)
- `source_priority`: object with `day_order` (array of enum strings: ["solar", "grid", "bess", "dg"], x-mutable: true), `night_order` (array of enum strings: ["grid", "bess", "dg"], x-mutable: true)
- `state_machine`: object with `loop_interval_ms` (integer, 500-2000, x-unit "ms", x-mutable: false — structural), `fault_retry_count` (integer, 0-10, x-unit "count", x-mutable: true)

`alarms_config.schema.json`:
- Root: `x-hot-reload: true`
- `defaults`: object with `hysteresis_pct` (number, 0-10, x-unit "%", x-mutable: true), `delay_ms` (integer, 0-30000, x-unit "ms", x-mutable: true)
- `rules`: object with `additionalProperties: false` containing named alarm rules. Each alarm rule is an object:
  - `signal` (string, required) — RTDB signal path
  - `severity` (enum: ["warning", "action", "protection"], required)
  - `high_threshold` (number, x-unit varies by signal, x-mutable: true)
  - `low_threshold` (number, x-unit varies by signal, x-mutable: true)
  - `hysteresis` (number, x-mutable: true)
  - `delay_ms` (integer, min 0, x-unit "ms", x-mutable: true)
  - `enabled` (boolean, x-mutable: true)

  For the `rules` section, use a fixed set of well-known alarm rule names as properties (not patternProperties): `cell_voltage_high`, `cell_voltage_low`, `cell_temp_high`, `cell_temp_low`, `soc_high`, `soc_low`, `pcs_overtemp`, `bus_voltage_high`, `bus_voltage_low`. This avoids patternProperties complexity while covering the key alarms.

`schedule_config.schema.json`:
- Root: `x-hot-reload: true`
- `mode` (enum: ["manual", "time_of_day", "curve"], x-mutable: true)
- `time_windows`: array of objects, each with `start` (string, pattern "^[0-2][0-9]:[0-5][0-9]$"), `end` (string, same pattern), `action` (enum: ["charge", "discharge", "idle"]), `power_kw` (number, x-unit "kW"). All fields x-mutable: true.
- `day_night`: object with `day_start` (string, HH:MM pattern), `night_start` (string, HH:MM pattern), x-mutable: true
- `power_curve`: array of 96 numbers (x-unit "kW", x-mutable: true) — 15-minute intervals over 24h. Use `minItems: 96, maxItems: 96` to enforce exactly 96 points.

**GROUP C: Infrastructure schemas** (cloud, network, gpio, hmi)

`cloud_config.schema.json`:
- `broker`: object with `host` (string, required), `port` (integer, default 8883, min 1, max 65535, x-unit "port"), `protocol` (enum: ["mqtts", "mqtt"])
- `auth`: object with `method` (enum: ["mtls", "token"]), `ca_cert_path` (string), `client_cert_path` (string), `client_key_path` (string)
- `telemetry`: object with `interval_s` (integer, 1-300, x-unit "s"), `topic_prefix` (string)
- `offline_buffer`: object with `enabled` (boolean), `max_hours` (integer, 1-168, x-unit "h"), `max_mb` (integer, 1-500, x-unit "MB")

`network_config.schema.json`:
- `interfaces`: object with `eth0` and `eth1`, each an object with: `mode` (enum: ["static", "dhcp"]), `address` (string — IP), `netmask` (string), `gateway` (string), `dns` (array of strings)
- Use if/then: if mode=="static" then require address, netmask, gateway

`gpio_config.schema.json`:
- `digital_inputs`: object with properties DI-0 through DI-7, each an object with: `name` (string, required), `description` (string), `active_low` (boolean), `debounce_ms` (integer, 0-100, x-unit "ms")
- `digital_outputs`: object with properties DO-0 through DO-7, each an object with: `name` (string, required), `description` (string), `active_low` (boolean), `initial_state` (enum: ["low", "high"])
- Strict enum on DI/DO names via the object property keys (not free-form strings).

`hmi_config.schema.json`:
- `server`: object with `http_port` (integer, 1024-65535, x-unit "port"), `websocket_port` (integer, 1024-65535, x-unit "port"), `host` (string, default "0.0.0.0")
- `auth`: object with `operator_pin_hash` (string — bcrypt hash stored as string, see research note), `admin_pin_hash` (string), `session_timeout_s` (integer, 60-7200, x-unit "s")
- `display`: object with `refresh_interval_ms` (integer, 500-5000, x-unit "ms"), `kiosk_mode` (boolean), `screen_size` (enum: ["7inch", "10inch", "15inch"])
