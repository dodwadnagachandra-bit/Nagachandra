Create `tests/integration/test_performance.py` with metric collection functions and test classes:

**Module-level marker:** `pytestmark = [pytest.mark.integration, pytest.mark.timeout(900)]`

**Imports:** pytest, time, signal, threading, zmq, msgpack, psutil, pyarrow.parquet, Path, dataclass. From conftest: ModuleProcess, MetricsCollector, PROFILES, BUILD_DIR, CONFIG_DIR, check_rtdb_exists. From ems_common.rtdb: attach_rtdb, detach_rtdb, EmsRtdb. From ems_common.ipc: SOCK_TELEMETRY.

**CLEAN_PASS_DURATION_S = 120** -- Shortened from 10 min to 2 min for practical dev testing. Mark full 10-min tests with `@pytest.mark.slow` for optional extended runs.
**FAULT_PASS_DURATION_S = 120** -- Same shortened duration.
**FULL_PASS_DURATION_S = 600** -- Full 10-minute pass for `--runslow` option.

**Metric collection functions:**

1. `def collect_gpio_latencies(duration_s: float = 60.0, sample_interval_s: float = 1.0) -> list[float]`:
   - Import gpio_harness RtdbBackend if available (skip if not)
   - Create RtdbBackend instance
   - For each sample: set DI pin, measure time until DO pin changes (tight poll loop, no sleep)
   - Clear DI after measurement
   - Return list of latencies in ms
   - If RtdbBackend cannot be imported or RTDB not available, return empty list

2. `def collect_rtdb_write_latencies(rtdb: EmsRtdb, duration_s: float = 60.0, sample_interval_s: float = 0.5) -> list[float]`:
   - For each sample: read `rtdb.system.last_update_ms`, compute delta from wall clock (`time.time() * 1000`)
   - Return list of absolute deltas in ms
   - Skip samples where last_update_ms is 0 (module not yet writing)

3. `def collect_zmq_lag(endpoint: str, topic: str, duration_s: float = 60.0) -> list[int]`:
   - Create SUB socket, subscribe to topic
   - Track sequence numbers: lag = current_seq - last_seq - 1
   - On timeout (5s no message): append 999 as severe lag indicator
   - Return list of lag values (gaps only, not zero-lag samples)

4. `def collect_rss_samples(modules: dict[str, ModuleProcess], duration_s: float = 60.0, interval_s: float = 1.0) -> dict[str, list[int]]`:
   - For each second: sample RSS for every alive module via `module.rss_bytes`
   - Return dict of module_name -> list of RSS values in bytes

5. `def count_parquet_rows(data_dir: Path) -> int`:
   - Find all `telemetry_*.parquet` files
   - Sum total rows across all files using pyarrow
   - Return total row count

**Class TestPerformanceCleanPass:**

Fixture `clean_system` (class scope):
1. Launch all modules + simulators with residential profile (clean mode -- no fault injection)
2. Create MetricsCollector instance
3. Run metric collection in parallel threads for CLEAN_PASS_DURATION_S:
   - Thread 1: GPIO latencies (if GPIO available)
   - Thread 2: RTDB write latencies
   - Thread 3: ZMQ lag
   - Thread 4: RSS samples
4. After collection, count Parquet rows for logger throughput
5. Populate MetricsCollector fields
6. Yield MetricsCollector + modules dict
7. Teardown: kill all

Test methods:

1. `test_gpio_latency_p99(self, clean_system)`:
   - Skip if no GPIO latency samples collected
   - Assert MetricsCollector.gpio_latencies_ms p99 < 100.0

2. `test_rtdb_write_latency_p99(self, clean_system)`:
   - Assert MetricsCollector.rtdb_write_latencies_ms p99 < 10.0
   - Skip if fewer than 10 samples (module may not be writing)

3. `test_zmq_lag(self, clean_system)`:
   - Assert max(MetricsCollector.zmq_lag_messages) < 5 (or empty list = no lag = pass)

4. `test_logger_throughput(self, clean_system)`:
   - Calculate expected rows: duration_s * 1 (1Hz) * num_topics
   - Assert logger_rows_written / logger_rows_expected >= 0.95
   - Skip if logger_rows_expected == 0

5. `test_rss_growth(self, clean_system)`:
   - For each module in rss_samples with >= 60 samples:
   - baseline = mean of first 60 samples
   - final = mean of last 60 samples
   - growth_pct = ((final - baseline) / baseline) * 100
   - Assert growth_pct < 10.0 for each module

**Class TestPerformanceFaultPass:**

Similar structure but with fault injection enabled:

Fixture `fault_system` (class scope):
1. Launch all modules + simulators
2. After 10s warmup, inject faults:
   - CAN sim: restart with `--frame-drop-rate 0.05` if supported, or set via env var
   - Modbus sim: configure DG timeout, BTMS exception
   - GPIO: set DI-1 stuck high via RtdbBackend if available
3. Collect metrics for FAULT_PASS_DURATION_S
4. Yield MetricsCollector
5. Teardown

Test methods: Same 5 tests as clean pass, same thresholds (performance must hold under load).

**Class TestContainerTopology:**

Fixture `container_system` (class scope):
- Same as clean_system but with container profile topology args
- Mark with `@pytest.mark.skipif(psutil.virtual_memory().total < 4 * 1024**3, reason="Need 4GB+ RAM for container topology")`

Test methods: Same 5 metric tests.

**Important implementation notes:**
- Use `threading.Thread(target=..., daemon=True)` for parallel metric collection so threads don't block test teardown
- GPIO latency measurement: tight polling loop (no sleep) for accurate timing, then `time.sleep(sample_interval_s)` between samples
- ZMQ lag: use `ZMQ_RCVTIMEO=5000` on SUB socket to avoid infinite hangs
- RSS growth threshold intentionally generous (10%) because container-scale RTDB is large
- The "expected rows" for logger throughput depends on topology: residential has 1 cluster topic + 1 system topic = 2/sec, container has 4 cluster topics + 1 system = 5/sec
- Fault injection tests should NOT fail on log errors (per CONTEXT.md: "Expected during fault injection -- NOT treated as failures")
- Total test runtime: ~8 min for shortened passes, ~40 min for full `--runslow` passes
