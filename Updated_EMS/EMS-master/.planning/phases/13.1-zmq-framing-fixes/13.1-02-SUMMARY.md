# Phase 13.1 Plan 02: ZMQ Framing Convention Tests Summary

ZMQ framing contract tests proving 2-frame PUB, single-frame PUSH, and shared socket patterns work correctly after 13.1-01 defect fixes.

## What Was Done

### Task 1: Update existing tests (1a4e961)

Updated `tests/test_safety_manager.py` TestZmqEvents to assert exactly 2 PUB frames instead of using `frames[-1]` with implicit 3-frame assumption. Comments updated to reflect removed length prefix frame.

Note: `tests/test_data_manager.py` TestHealthMonitor was already updated in Plan 13.1-01 to use the shared socket pattern (`HealthMonitor(rtdb, pub, stale_threshold_ms=5000)`). No further changes needed.

### Task 2: Add dedicated ZMQ framing verification tests (cac7d8c)

Created `tests/test_zmq_framing.py` with 6 tests across 3 classes:

**TestPubFraming** (DEFECT-3 verification):
- `test_python_pub_sends_two_frames` -- PUB sends [topic, body], SUB receives exactly 2 frames with valid msgpack envelope
- `test_sub_rejects_three_frame_messages` -- 3-frame messages are distinguishable (would be dropped by telemetry_writer's `len(parts) != 2` filter); valid 2-frame messages pass through

**TestPushPullFraming** (DEFECT-2 verification):
- `test_push_single_frame_decoded_by_event_consumer` -- Single msgpack frame sent on PUSH, received on PULL, decode_event succeeds with correct fields
- `test_push_with_length_prefix_fails_decode` -- Old [4-byte len | SNDMORE] [body] framing causes PULL recv() to get 4-byte prefix that fails decode_event

**TestSharedPubSocket** (DEFECT-1 verification):
- `test_health_and_publisher_share_socket` -- One PUB socket, two senders (telemetry + health), one SUB receives both topics
- `test_double_bind_same_endpoint_fails` -- Second bind to same TCP endpoint raises zmq.ZMQError

## Verification Results

- All 6 new framing tests pass
- Full test suite: 287 passed, 5 skipped, 0 failures
- No regressions introduced

## Deviations from Plan

None -- plan executed exactly as written. The only note is that test_data_manager.py health monitor tests were already updated in 13.1-01, so Task 1 only modified test_safety_manager.py.

## Decisions Made

1. **Health monitor tests already current**: Plan 13.1-01 already updated TestHealthMonitor to use shared socket constructor. No duplicate changes needed.
2. **TCP port range 15570-15579**: Dedicated range for framing tests avoids conflicts with existing tests (15550-15561).
3. **Length-prefix decode test**: Uses `pytest.raises(Exception)` with fallback assertion to handle edge case where 4 bytes might accidentally be valid msgpack but not a valid event dict.
