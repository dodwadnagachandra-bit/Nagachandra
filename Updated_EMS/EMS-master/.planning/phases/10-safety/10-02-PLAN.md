  <name>Task 1: Watchdog management with condvar-based feed thread</name>
  <files>src/safety_manager/src/watchdog.h, src/safety_manager/src/watchdog.c</files>
  <action>
Implement /dev/watchdog hardware watchdog management with a dedicated higher-priority feed thread.

**watchdog.h:**
- `int watchdog_open(const char *dev_path, int timeout_sec)` -- opens device, sets timeout via WDIOC_SETTIMEOUT. Returns fd, or -1 on failure (EBUSY = another process has it, log warning and continue without watchdog per Pitfall 6).
- `void watchdog_kick(int fd)` -- calls ioctl(fd, WDIOC_KEEPALIVE, NULL).
- `void watchdog_close(int fd)` -- writes magic character 'V' then closes fd (proper disable).
- `int watchdog_thread_start(int wdt_fd, int sched_priority)` -- creates pthread with SCHED_FIFO at given priority. Thread waits on condvar for scan completion signal, then kicks watchdog. Returns 0 on success.
- `void watchdog_thread_stop(void)` -- signals thread to exit, joins.
- `void watchdog_signal_scan_complete(void)` -- called by scan thread after each complete cycle. Sets flag and signals condvar.

**watchdog.c:**
- Static globals: `pthread_mutex_t wdt_mutex`, `pthread_cond_t wdt_cond`, `volatile bool scan_complete`, `volatile bool wdt_running`, `pthread_t wdt_thread`.
- watchdog_open: `open(dev_path, O_RDWR)`. Handle EBUSY (return -1 with errno). Set timeout via ioctl WDIOC_SETTIMEOUT (non-fatal if unsupported). Default timeout: 2 seconds per research recommendation.
- watchdog_thread function (runs at SCHED_FIFO priority, e.g., 81):
  - Loop while wdt_running: lock mutex, wait on condvar with 1-second timedwait timeout. If scan_complete is true, clear it, unlock, kick watchdog. If timedwait expired without signal (scan thread stuck), log WARNING but still kick watchdog (per Pitfall 3 -- process is alive, scan delay is not process death). If wdt_running becomes false, exit.
- watchdog_thread_start: set pthread attr with SCHED_FIFO and given priority. Use `pthread_attr_setinheritsched(&attr, PTHREAD_EXPLICIT_SCHED)` to ensure the thread actually gets the specified priority instead of inheriting parent. Create thread.
- watchdog_signal_scan_complete: lock mutex, set scan_complete=true, signal condvar, unlock.
- watchdog_close: write 'V' magic character to properly disable watchdog before close.

Note: If /dev/watchdog is unavailable (dev environment without hardware watchdog), watchdog_open returns -1 and the scan loop continues without watchdog. The thread is not started. This is the expected dev/CI behavior.

  <name>Task 2: ZMQ safety event publishing and reset command handler</name>
  <files>src/safety_manager/src/safety_event.h, src/safety_manager/src/safety_event.c, src/safety_manager/src/safety_reset.h, src/safety_manager/src/safety_reset.c</files>

Implement ZMQ-based event publishing and reset command handling.

**safety_event.h / safety_event.c:**
- `typedef struct { void *zmq_ctx; void *pub_sock; void *push_sock; uint64_t seq; } safety_event_ctx_t;`
- `int safety_event_init(safety_event_ctx_t *ctx, const char *pub_addr, const char *push_addr)` -- creates ZMQ context, PUB socket connecting to telemetry (NOT binding -- data_manager owns the PUB bind), PUSH socket connecting to logger. Set ZMQ_SNDHWM on both sockets (e.g., 100). Returns 0 on success, -1 on failure (non-fatal: safety continues without event publishing).
- `int safety_event_publish(safety_event_ctx_t *ctx, const char *event_type, const char *message, ems_severity_t severity)` -- encodes MessagePack envelope using mpack:
  - Map with 5 keys: ts (CLOCK_REALTIME as double), seq (incrementing uint64), src ("safety_manager"), topic ("gpio"), payload (inner map with event_type, message, severity).
  - Length-prefixed framing: 4-byte BE uint32 length before MessagePack body.
  - Send on PUB socket: topic frame (ZMQ_SNDMORE | ZMQ_DONTWAIT), length prefix (ZMQ_SNDMORE | ZMQ_DONTWAIT), body (ZMQ_DONTWAIT). If EAGAIN, drop silently -- safety outputs are priority.
  - Send on PUSH socket: length prefix (ZMQ_SNDMORE | ZMQ_DONTWAIT), body (ZMQ_DONTWAIT). If EAGAIN, drop silently.
  - Use a stack-allocated buffer (char buf[512] per research) -- no heap allocation in the hot path.
  - Returns 0 on success, -1 if mpack encoding fails.
- `void safety_event_close(safety_event_ctx_t *ctx)` -- closes sockets and context.
- Include convenience functions for common events: `safety_event_estop(ctx)`, `safety_event_fire(ctx)`, `safety_event_flood(ctx)`, `safety_event_gpio_failure(ctx, const char *detail)`, `safety_event_reset(ctx, const char *what)`.

**safety_reset.h / safety_reset.c:**
- `typedef struct { void *zmq_ctx; void *rep_sock; } safety_reset_ctx_t;`
- `int safety_reset_init(safety_reset_ctx_t *ctx, const char *bind_addr)` -- creates ZMQ context (or accepts shared one), binds REP socket. The reset socket binds on a safety-specific address, e.g., `ipc:///run/ems/safety_cmd.sock` (define a new constant or use a parameter). Returns 0 on success.
- `int safety_reset_poll(safety_reset_ctx_t *ctx, safety_state_t *state, const uint8_t *di_raw, const gpio_config_t *config)` -- non-blocking ZMQ poll (0 timeout = immediate return). If message available:
  - Decode MessagePack request: expect `{action: "safety_reset", source: "hmi"|"operator"}`.
  - Call `safety_reset(state, di_raw, config)` from response_matrix.h.
  - Send reply: `{status: "ok"}` on success, `{status: "error", error_msg: "inputs still active: estop/fire/flood"}` on failure.
  - Returns 1 if reset was processed, 0 if no message, -1 on error.
- `void safety_reset_close(safety_reset_ctx_t *ctx)` -- closes socket.
- All ZMQ operations use ZMQ_DONTWAIT where appropriate.
- Note: safety_reset.c includes response_matrix.h for the safety_reset() function and safety_state_t type. This creates a compile-time dependency on Plan 01's output. Since both plans are Wave 1, the executor should compile after both are complete. If building incrementally, forward-declare or stub the types.
